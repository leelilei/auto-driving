## 1. 目标与合格的含义

核心问题：在自然语言 POI 路线规划中，能否根据候选解析的规划后果，更有效地分配有限的复核预算？

研究对象是固定合成图上的离线 POI 行程规划，不包括车辆控制、多模态感知、真实道路安全或实时交通。不训练新模型，不接入商业地图，不要求复现缺少场景数据的原 MSGS 实验。

验收分为三个层次，不能混为一谈：

1. **工程合格**：接口、算法、失败处理、日志和复现通过检查。
2. **实验合格**：数据有审核证据、划分无泄漏、基线公平、指标正确、成本真实。
3. **研究主张成立**：结果支持决策门控的增量；不是脚本跑通就成立。

没有效果的实验也可以工程和实验合格。不得为达到预期提升而挑选数据、改标签、删失败或反复挑最好的一次。

## 5. 受控图与精确求解规范

### 5.1 环境

每图固定起终点、出发时间、10 个 POI（五类各两点）、坐标、评分、评价数量、开闭店、停留时长、距离与速度。始终包含五类，不能用“图中只有正确类型”泄漏任务。每意图绑定一张冻结图，四种表达共用，同一方法间也共用。

保留当前坐标距离和固定速度模型，并称为合成图。正式图版本需保存生成参数、seed、全部属性与 SHA256。

正式开发前定义三类场景：宽松、时间敏感、质量—距离权衡。优先延续现有生成器；agy 应提交具体参数表、预期数量和结构诊断，再冻结，不根据模型输赢选参数。Pilot 可先使用已冻结的宽松图完成 E1，但必须报告约束缺少触发机会的限制；图分布改变后另建实验版本，不覆盖旧结果。

主集要求 gold 请求完整可行。允许固定种子序列、每组最多 20 次重采样，按结构可行性选择第一个合格图，记录每次尝试；禁止依据模型表现筛图。失败时按预先规定的替换规则处理。报告这种条件采样，不称为真实流量分布。

### 5.2 求解语义

约束检查：允许等待开门；服务完成不能晚于闭店；最终到达不能晚于 T；时间统一为分钟。未知类别、无效时间、越界/NaN 权重、循环依赖、未请求类别的依赖端点均显式拒绝。

每类最多访问一个候选，只访问请求的任务节点。先满足硬约束，再最大化类型覆盖数，再最大化效用，再按稳定 POI ID 元组打破平局。部分覆盖中先后约束只在两端均被访问时比较；缺失请求仍被独立 gold 任务评价判为失败。不要让该约定把部分任务伪装成完整成功。

五类各两候选的非空序列上限为 6,330，加直达共 6,331。可以按覆盖数从高到低枚举、在某覆盖层完成全部搜索后停止；不能找到第一条可行路线就退出。空请求的直达路线也必须检查 T；非空任务无可访问 POI 时保持显式失败，不能记成功。

### 5.3 效用

`U_w(r) = w Q(r) - (1-w) Dbar(r)`。

为复用当前实现，Q 为访问 POI 平均质量；每点质量为归一化评分与对数评价数各占一半。评分缩放当前为 `(rating-3)/2` 截断到 [0,1]，评价数为 `log(max(10,reviews))/log(1000)` 截断到 [0,1]。将精确公式锁进场景配置，所有方法一致。空路线 Q=0。

`Dbar = 总距离 / (6 × 全图最大边距离)`。零最大距离图在生成时拒绝；缩放不能随预测任务或路线改变。评分、门控与参考解统一用同一个效用定义。

当前 RouteResult 会四舍五入部分输出。正式实现必须为门控与统计保留未舍入浮点值，显示层才取小数；写文件再读回不能改变结果。效用平局容差固定为 1e-9，时间容差固定为 1e-4 分钟并在测试覆盖边界。

### 5.4 独立检查

不能只用求解器自己的函数证明自己正确。增加手算图和独立小规模枚举：截止边界、闭店边界、等待、反向依赖、遗漏依赖、无解、部分覆盖、别名、同分平局、坐标序列化、偏好极值、空请求。图规模两三类时比较独立参考解的最优覆盖与效用。

独立 gold 评估器重算时间和依赖，不能信任预测结果里的 `is_full_coverage`、`is_valid` 或已四舍五入时间。保留历史错误样例作回归测试。

## 6. A/B/复核与决策门控

A 直接读取原句输出结构；B 从同一原句逐字段提取证据并输出同一 schema。两者不互看、不假设独立。基础模型、版本、输出预算一致，额外提示长度按实际 token 计费。

结构为 `H=(sorted(S), T, closure(D))`。以下任一条件构成保护触发 h=1：A/B 无效；H 不同；任一路规划异常/无解；两路覆盖数不同。即使路线一样，也保留结构分歧触发。

只有两路均有效、结构一致、规划成功且覆盖相同才计算：

`delta_U = max(|U_wA(rA)-U_wA(rB)|, |U_wB(rA)-U_wB(rB)|)`。

`g_DARC = h OR (delta_U > tau)`。不存在路线时 delta_U 为 null，不代填 0、NaN 或无穷值混入比较。该信号不读取 gold，且不是“真实 regret”。

未触发保留 A；触发后仅一次复核。复核器读原句、两个候选和字段差异，不读路线、效用、触发分数、gold 或参考解。输出完整结构和简短证据；有效即采用。无效则依次回退有效 A、有效 B；都无效则失败。不得拼接多数票字段、取平均权重或循环复核。

## 8. 参数选择与预算公平

Pilot 20 组用于修复实现和一次有限提示迭代；Calibration 20 组用于选阈值。Test 不参与任何选择。小开发集不足以保证稳定选择，需报告限制。

- tau 网格：0、0.01、0.025、0.05、0.1、0.2、关闭效用触发。
- tau_sem：同一网格，加 0.5、1、关闭权重触发。
- 目标复核率：0.25、0.5、0.75；主运行预定为 0.5 档。
- 对满足开发预算上限的阈值，先最大化开发 TSR，再最小化实际 token；再并列选更高阈值。没有可达档位则记录不可达，不能关闭保护 h。
- B3 的 p 根据开发 h 的发生率匹配目标总复核率；固定种子，用样本 ID 与种子生成稳定均匀数，不受线程调度影响。

测试报告真实 q 和 token；相同调用数不等于相同 token。离线相同配额分析作为补充：公共保护集合之外，按信号排序选择同样数量，与随机选择比较。配额预定，平局由固定随机种子处理。不得称为单请求在线阈值策略。

模型默认复用已配置的 FHL/gpt-5.4-mini，准确保存请求模型 ID、服务商、参数及日期，不擅自换成更贵模型。若接口不支持 temperature/seed，记录 omitted/unsupported，不伪称确定性。缓存应区分温度字段省略与显式零。

## 9. 指标定义与统计

### 9.1 任务与一致性

对主集完整可行任务，A_ik=1 当且仅当输出合法、覆盖全部 gold 请求、满足 gold 时间、依赖和营业时间；其他为 0。所有失败进入分母。

- `TSR = mean(A_ik)`。
- `GTSR = mean_i(product_k A_ik)`，每组固定四句。
- 按 V0/V1/V2/V3 分别报 TSR；报告改写相对原句的配对变化。
- Route Flip：每组 6 个表达对中稳定 POI 序列不同的比例，再对组平均。仅在两侧路线均有效的表达对上计算翻转比例，再对至少有一对有效路线的组平均；同时报告有效组数和有效对数。没有有效对的组记 NA，不填零。无效表达对占全部每组6对的比例另报，不能把两个失败视为一致成功。路线变化本身不是任务错误。
- POI F1：集合 F1；双方空记 1，只有一方空记 0。依赖 F1 对闭包计算，同样明确空集合规则。
- 时间准确率：标准化 T 精确匹配；偏好方向准确率只用可判定人工标签。
- 解析完全失败：该句所有语义正确性记 0，单列格式/传输/规划失败。

### 9.2 校准效用

仅对成功完成 gold 任务且偏好可判定的路线计算：`L_U=(U_weval(r*)-U_weval(r))/2`。r* 是同图、gold 约束、完整覆盖和同权重的精确最优路线。它是受控校准损失，不是真实用户后悔值。

同时报成功且可计算效用的样本数；主图可另列失败赋损失 1 的惩罚敏感性结果。条件效用和全体 TSR 一起读，避免幸存者偏差。把权重映射改为 0.65/0.5/0.35 与 0.85/0.5/0.15，重新算参考解及评价，用于敏感性分析，不用测试结果挑一种映射当主结果。

### 9.3 门控诊断

逐例记录复核前后任务状态、硬字段、效用；统计纠正、改坏、未变、触发但无收益、未触发却错误、保护触发和额外效用触发。只有额外效用触发相对 B5 有可解释增量，才可能支持决策信号价值。

### 9.4 统计单位

按意图组计算均值和配对差，再对组做 2,000 次 bootstrap，固定种子 20260906，报告 95% 差值区间。若仍有更高层语义簇，按簇重采样；绝不把 640 句或重复调用当作 640 个独立意图。

主比较为 Ours 对 B4、B3，B5 用于增量来源判断。若声明多重显著性，使用 Holm 校正并预先列检验族；其他分层标为探索性。

预先选定 40 个测试组，对 B0/B4/B6/Ours 做三次独立候选库运行。主运行作为第 1 次，增加两次；每次重调模型，不能复制缓存假装独立重复。数据和阈值固定，随机基线的掩码重复与模型重跑分别记录。

## 10. 成本、失败、缓存与可复现

每次 API attempt 记录：run/call/sample ID、阶段、模型配置哈希、提示哈希、开始结束时间、输入输出 token、usage 来源、返回状态、格式校验、错误类别、retry parent。密钥只能来自环境变量，严禁进入日志。

分开报告两种成本：实验实际账单（包括生成/审核辅助/完整候选库）与各方法部署成本（只计该方法实际需要的调用）。B0 计 A；B2 计 A+B；门控方法计 A+B+触发复核；B6 计三次；B1 计 A/A2/A3。规划、缓存命中、最终规划和总时长同样分开。

Provider usage 优先；缺失时估算明确标注，不混入“真实 token”。失败调用是否收费未知时记录 unknown。并行各调用延迟之和不是端到端 wall time；离线回放时间也不是在线推理延迟。需要延迟主张时另做小规模、固定并发的实际运行。

默认并发最多 3、每调用 timeout 45 秒、输出上限 1,600 tokens；生成较长改写可以单独配置，但必须记录。正式候选库不自动重试语义或格式错误。网络失败默认不自动重试；另开补测运行、关联原 attempt，主表保留首轮失败，补测表单列。不能把补测成功覆盖原失败。

缓存键至少包含：输入文本、完整提示版本、模型/服务商/接口/解码参数、sample draw ID、用途。规划缓存还包含图哈希、意图、求解器/效用版本。A2/A3 不能因 prompt 相同误用 A 缓存。缓存键不包含用于泄漏的 gold 内容，推理不读取 gold。

支持：dry-run 列计划不调用 API；resume 不重复已完成 attempt；离线 replay 网络调用数为零；预算达到时保存可恢复状态。生成失败、拒答、缺字段、截断、不完整流响应不能标成有效完成。不得用正则截取片段掩盖未完成响应；如果容许去除 Markdown 围栏，统一规则并保存原文。

建议预算上限（工程限额，不是预期效果）：Pilot 生成与 A/B/复核合计最多 300 attempts；640 句主候选库 A/B/review/A2/A3 约 3,200 attempts，上限先设 3,600；其他阶段分别配置。启动前打印规模、用途、上限，不能隐式跑全库。实际 token/金额限额由 run config 显式给出；失败收费未知时不能保证精确账单上限。

## 12. 分阶段执行与停止条件

### P0：工程准备

复跑现有测试、审计 schema/精度/日志，完成统一执行器、缓存和离线评价。构造 mock fixtures 专门覆盖故障；mock 结果必须独立目录且不能进入论文表。

交付 E0 证据与验收清单。若原有测试失败，不靠删测试通过；先说明原因并修复。

### P1：数据准备与正式 Pilot

完成 20 组原句核验材料、3 个等义候选、候选划分和泄漏检查。没有人工确认时继续完成工程工作，提交待审核材料，并把正式 Pilot 标为 blocked_on_annotation，不能自动批准。

人工审核和协议版本就绪后运行 E1，输出 B0/B6、失败、净纠错、语义/图分层与成本。若基线几乎全对或始终复核无净收益，最多在开发集做一次有记录的提示修改；仍无收益则交付 no-go/inconclusive，不擅自扩大到 Test。

### P2：门控与校准

实现全部基线，在开发数据上分解结构触发和效用增量；冻结参数。只有表示差异而没有决策差异时，报告信号退化。仅 B0 较差不足以证明 DARC 有效。

### P3：主实验

通过数据与实现验收、完成开发选择并满足研究继续条件后，按冻结 manifest 一次运行 E3/E4/E5。不得一边看 Test 表一边调参。实现 bug 若影响结果，记录受影响范围、另开修正版运行，保留旧数据；研究设计变化则需要新的未见测试集或明确降级为探索性。

### P4：交付与论文判断

完整打包，离线重算所有主表。区分“实验有效但没有收益”和“实验无效”。若希望声称相对 B6 质量接近，预先使用 TSR 降低不超过 2 个百分点的工程容忍界限，并以配对区间支持；不能把不显著当等效。15% token 节省是设计目标，不是必须做出来的数字。
