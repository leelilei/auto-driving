1. **正向信号与显著性边界**：

3. **Gemini 的极端底噪特性**：
   - Gemini-3.1-flash-lite 在历史测试集上的初始底噪极低（B0 翻转率仅 4.69%，排除漂移组后仅 3.42%），由于基数极小，复核收益被压缩在 0.30 pp ~ 0.34 pp 的极窄区间内。

### 2.3 结构保护项 $h$ 与 10% 配额可行性审查

Codex 明确指出：*“先确认共同结构保护 h 是否已超过 10% 配额；超过则该低配额实验不可行，不能强行截断保护项。”*
经对全部 640 句的图结构、候选 POI 类别与拓扑时序进行严格求解：
- **DeepSeek-v4**: $h=1$ 触发数仅为 **2 次**（占有效对的 0.49%，占全 640 句的 0.31%）；
- **Qwen3.8-max**: $h=1$ 触发数为 **0 次**（0.00%）。

**审计结论**：
1. **$h$ 保护项远未耗尽 10% 配额**（640 句的 10% 预算为 $K=64$，$h$ 仅占 0 ~ 2 个名额），因此不存在“保护项打爆预算”的技术瓶颈；
2. **真正的致命硬伤是反事实缓存破碎**：由于第三方代理严重丢包，DeepSeek 缺失了 233 句复核结果，Qwen 缺失了 110 句。如果强行把缺失的复核填补为回退至 A，或者用残缺的 406 组代替全量 640 组，会产生严重的样本选择偏差；
3. **彻底正名模型能力**：必须在论文中明确写明，DeepSeek-v4 的低分纯属历史采集时不稳定代理节点的工程故障，不能作为模型自身规划能力低下的论据。

## 3. 第三步：Claude 全量实验扩量决策与学术研判

根据前两步的审计结果，结合目前已完成的 **Claude Haiku 4.5 与 Claude Sonnet 4.6 在新版 E2 确认集上的完整实验**，我们对“是否补跑 Claude 120 组以凑齐 160 组”作出深入评估：

### 3.1 收益与代价权衡分析

1. **调用与时间成本**：
   - 补齐 120 组需要：$120 \text{ 组} \times 4 \text{ 句} \times 3 \text{ 调用} = \mathbf{1,440} \text{ 次 API 真实调用}$；
   - 加上网络重试与格式自适应，预计耗时 2~3 小时。
2. **边际学术收益评估**：
   - **现有资产已足够回答关键问题**：当前 Haiku 4.5 在 40 组（160 句，480 调用）上的表现已非常确凿：
     - B0 初始翻转率为 **6.25%**（底噪已显著低于 GPT 家族的 20%~23%）；
     - B6 全量复核发生 **1 次改坏**（TSR 从 100% 跌至 99.38%）；
     - DARC 凭借 1.88% 的极小复核率守住了 **100% TSR（0 次改坏）**，同时实现了 +1.06 pp 的翻转率增益。
   - **扩量无法改变其核心物理性质**：Haiku 的初始翻转率极低，即使扩量至 160 组，其点估计也会稳定在 5%~6% 之间，无法获得像 GPT-5.4-mini 类似的大幅度净增益。Haiku 的核心学术价值在于**防御复核改坏**，而非依靠复核翻盘。
3. **科研风险（防范事后扩量偏差）**：
   - 正如 Codex 指出：*“先固定协议和样本数，不以跑出显著结果为停止条件。扩大样本能减少抽样不确定性，但不能消除接口失败、标签漂移或事后选择偏差。”*
   - 若此时为了追求“表格数字整齐”或“刷出 $p<0.05$”而临时追加调用，违背了预注册实验的严谨性。
