# DeepSeek候选依赖文字化与路线顺序对照

## 冻结设计

沿用24个作者注入候选错误的案例、8个已暴露母意图；不改原句、候选、gold或图。两个方法各独立请求2次，共96个逻辑请求，双方均重新采集，不复用上一轮答案作对照。

- `dependency_text`：只读取候选dependencies，用固定句型“Visit X before Y.”表达每条依赖；空依赖明确说明候选未指定访问顺序。不读取原句、gold、地图，不调用求解器。
- `route_order`：与上一轮信息消融中的route_order相同，提供A/B实际规划路线的类别顺序。

两组共用相同HEADER、原句、A/B候选与字段差异名称，原句只出现一次；按案例和重复轮次交替调用顺序。文字化函数为纯确定性格式转换，事先通过空依赖、单依赖检查；48组公共提示前缀一致。

模型使用DeepSeek官方`deepseek-v4.1-flash-expires-on-0910`，temperature=0，输出上限1600、120秒、8路并发。timeout与并发在本轮首次请求前固定；先一项真实请求预检。鉴权失败或整批传输失败停止；传输项最多各恢复1次、最多16项；schema及有效答案不重试。原始失败保留，schema失败沿用回退A规则并同时报告原始结果。

主比较route_order−dependency_text的硬约束与偏好方向联合正确率。附TSR、纠正/改坏、token、逐重复与错误族结果。方向评分沿用w>0.6质量优先、w<0.4距离优先，其余均衡；不是原句精确数值真值。完整96项有终态且无未解决传输失败才做效果汇总。

## 解释边界

如果路线顺序没有稳定优于文字化依赖，现有结果不足以证明必须调用规划器；若优于，也仅支持继续测试，不自动证明复杂数值决策报告有效。两组在自然语言/列表表达、部分顺序/完整访问顺序、文本长度上仍有差异，本实验不能将所有效果单独归因为求解计算。

母意图仅8个，重复不增加独立样本数。全部错误和改坏均保留，不能围绕已发现获胜样本再挑图或改标签。尤其pilot_06方向解释争议沿用原冻结标签并披露，不按新答案改gold。

## 差异来自哪里

逐条核对8个不一致单元的原句与原始响应：路线组5次独有正确全部是偏好方向判断差异，双方相应的硬约束均正确。依赖文字组在这些案例中把效率优先解释为均衡或质量优先；没有观察到路线组独有正确来自修复依赖顺序。

路线组3次独有错误分别为：

1. `missing_deadline_3`第1次（pilot_06）：把效率优先解释为均衡。
2. `reversed_order_2`第2次（pilot_02）：截止字段输出`today`造成schema失败，回退反向依赖A。
3. `common_error_2`第1次（pilot_02）：引用了正确的“先超市后药房”原文，却仍输出反向依赖。

各错误族合计中，两组反转顺序都为7/8、共同错误都为5/8；路线组最终语义净增来自额外顺序族和两候选都正确族各1例，但这两例差异实际都发生在偏好字段，不能用注入错误族名称代替真正的纠错归因。

pilot_06的“efficiently”方向解释仍沿用旧冻结gold，未事后修改。母意图分层差异另存`interpretation_audit.json`；不以删去争议意图后的更好分数替换完整主表。

## 研究判断

本轮不支持“必须使用求解器得到路线顺序才能有效复核”。无需规划器的依赖文字化已达到更高的硬约束和任务成功率；实际路线顺序的少量语义优势来自偏好方向而非目标依赖纠错，且成本更高。也不能据此证明规划器在所有任务上无用，因为样本是8个母意图的受控开发构造，表达格式、完整/部分顺序等混杂仍未完全排除。

结合上一轮完整报告对路线顺序的有限增量，当前应暂停以“复杂决策反馈有独特收益”为前提的确认性扩量。无需为追求正结果继续围绕这24例调提示或挑模型。若继续研究，先重新明确规划信息能提供语言重述无法提供的哪种可验证证据，再用独立新开发设计测试；本批结果不解锁论文写作，也不自动改变proposal生效版本。
