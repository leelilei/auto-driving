# Reviewer 2

## 审阅范围与总体判断

本报告独立依据冻结的 `review_packet` 撰写，未阅读其他审阅意见，未联网。以下路径均相对于该包。评价标准为 EI 会议研究方案阶段的可信贡献与可执行证据，不采用 Nature 的选择性门槛。

目前最有价值的是一个可否定的问题，即同样复核一次，规划后果是否比语言或字段说明带来额外纠正。作者已经认真区分语义忠实性与规划可行性，也允许简单系统胜出。然而，目前尚未建立能够支撑方法论文的独特增量。现有材料支持暂停当前计算事实复核扩量、重新界定贡献，不支持宣布整个决策对比方向已被否定。

必须分开两条路线。历史 v5.1 使用 S/T/D/w、两个独立候选、交叉路线检查及双向单字段替换，再进行一次语义复核。后续场景任务采用三字段规则、单候选与候选场景事实表。后者并不是历史方法的忠实消融或复现。依据为 `docs/plans/proposal.md` §5.1、§5.2，第78至103行；`docs/plans/SCENE_GROUNDING_REASSESSMENT_20260910.md` §3，第33至44行；`9-AutoDriving-core/src/scene_policy.py` 第17至32、127至136行。

## 感兴趣的读者与已有优点

自然语言规划接口、工具辅助推理和旅行规划评测研究者会关心，外部计算究竟修正语言误读，还是只替模型完成算术。当前材料不足以面向车辆控制或真实道路安全作结论，作者对此的范围限定合理。

主要优点如下。

- 历史方案明确将字段差异复核列为主要对照，设置交叉约束与单字段消融，不以“使用求解器”或“增加复核”充当创新。依据为 `docs/plans/proposal.md` §3、第50至60行及§8。
- 跨图固定候选的设计能区分同一误读在不同决策条件下的影响，并明确图不能创造用户意图。依据为同文件第107至111、140至142行。
- 后续实现将场景事实计算、预测规则执行和 gold 评价分离，代码中事实生成器仅接收 scene，执行器要求经过验证的预测 Policy。依据为 `9-AutoDriving-core/src/scene_policy.py` 第67至114行。这是可审查的工程优点，尚不等于整条采集链已通过独立验收。
- 方案承认重复调用不增加独立意图数、历史开发暴露不能充作未见测试，并将不支持增量列为停止条件。依据为 `docs/plans/proposal.md` 第148至154、312至329行。

## Major Concerns

### R2-M1

- **Severity** Major
- **Blocking** Yes
- **Axis** originality，novelty-significance
- **Claim pointer** `docs/plans/proposal.md` 第29行、§3及第306行，拟贡献为候选解释后果对比及其复核增量；后续调整稿第59行，拟贡献为错误类型区分与场景最小变化评测。
- **Evidence pointer** `sources/LLMAP/README.md` 第7、12至23行；`sources/TripCraft/README.md` 第20至22行；`sources/PTS/README.md` 第5至20行；`sources/FlexTravelBench/README.md` 第18至24、45至49行；`sources/TravelBench/README.md` 第25至33行；`docs/plans/proposal.md` 第46、60、70、306行。
- **Evidence status** located；精确近邻算法的完整原文比较尚不可评估。

已有来源覆盖语言到偏好与约束解析、时空旅行规划、符号请求、约束变化和多轮偏好获取。将新任务改成场景依赖 POI 选择，或加入结构化规则与执行器，本身尚不能建立原创性。历史 v5.1 的潜在增量更窄，可能在“候选意图交叉规划加字段替换后果，是否改善原句复核”，但方案也明确承认该组合的近邻核查未完成。包中没有 CRITIC、RouteLLM 等被提及方法的完整原文，不能把作者的概览当作已核实的不重合证明；同样不能据此断言它们已经实现了相同方法。

这一问题阻断的是把现有系统命名为新方法并进入论文主张，不是要求方案阶段已经取得正结果。对于 EI 会议，扎实的窄增量或受控失效研究可以成立，不必另造通用规划框架，但必须说明究竟新增了什么可检验知识。

**Resolution test** 分别为历史方法和保留的新任务建立按输入、反馈内容、修订对象、求解器职责及评测干预划分的最邻近工作比较。若精确方法增量未能成立，允许转为预先明确的边界或诊断研究，但需指出现有研究没有回答的具体问题及其可复用证据；不能仅以自建任务命名替代区别。

### R2-M2

- **Severity** Major
- **Blocking** Yes
- **Axis** technical soundness，mechanism-evidence
- **Claim pointer** `docs/plans/proposal.md` §4，第67至70行，规划后果须优于字段信息且收益不能只来自提示；调整稿第27、40至44行，计算证据须提供语言复核之外的净收益。
- **Evidence pointer** `9-AutoDriving-core/results/scene_rule30/20260910T160632Z_glossary60_complete/summary.json` 第8至51行；`9-AutoDriving-core/results/scene_fair30/20260910T163441Z_haiku_reviewed/summary.json` 第11至44行；`9-AutoDriving-core/results/fair30_interface/20260910T171241Z_haiku_2x2/summary.json` 第2、47至83行；`docs/plans/SCENE_GROUNDING_REASSESSMENT_20260910.md` 第9至15行。
- **Evidence status** located；历史 v5.1 三轮实验仅有作者汇总，底层记录未在本包提供。

后续开发证据没有显示计算事实的稳定独特收益。术语说明对照的对象成功为60/60，所列证据参考方法为48/60，且术语说明的原始成功为57/60，最终满分包含回退。Fair30中语言复核59/60、证据复核57/60，后者12次回退。接口澄清后的两组对象成功均29/30；证据组规则正确27/30、语言组25/30，说明不能把任务打平说成所有维度等价，但尚不足以确认任务层增量。对应 token 分项总和为51085与33383，语言组另有一次 usage 未知，故也不宜把这一比值直接写成精确总成本增幅。

这些观察使“当前计算事实复核值得扩量”的论据不足，也提示原先改善可能受接口语义和输出格式影响。它们并没有直接否定历史 v5.1，因为候选数量、反馈对象、字段和任务都已经改变。调整稿所列历史注错实验是有边界的负面线索，不能被后续更容易的任务结果补成完整机制否证。

**Resolution test** 先明确保留哪一项主张。若保留历史方法，需对应其真实候选与报告结构，在冻结的独立任务上同场比较字段说明、交叉约束和完整报告；若保留场景事实复核，先说明语言复核之后尚存什么可纠正错误及计算信息如何针对它。报告回退前后、规则和对象终点、配对纠正与改坏，以及真实成本。当前证据允许停止这条实现，也允许提出有理由的新假设，不支持通过继续改同一开发集获得“显著提升”。

### R2-M3

- **Severity** Major
- **Blocking** No
- **Axis** scientific importance，audience relevance，data-resource-quality
- **Claim pointer** 调整稿第25至29、52至59行，场景依赖任务的研究价值及外部验证候选；`docs/plans/proposal.md` 第27至29、288至293行，HIPP扩展与可信量化贡献。
- **Evidence pointer** `9-AutoDriving-core/src/scene_policy.py` 第7、17至32、49至65、70至98行；`sources/TravelPlanner/README.md` 第36至40、74至79、134至145行；`sources/TripCraft/README.md` 第22至34行；`sources/TravelBench/README.md` 第16至18、29至33、93至96行；`sources/PTS/README.md` 第16至20行。
- **Evidence status** located。

现有三字段 DSL 固定家、银行、药房顺序，处理三个选择准则、营业参照和回家期限，使用欧氏距离、固定速度、无等待。这是清晰的内部夹具，却尚未说明该误读在公开真实任务中有多普遍、哪个较难的能力会影响实际成功。完整旅行基准含交通、住宿、事件或多轮用户交互，不能因主题都叫旅行规划就视为同一测试。

外部适配还有实际边界。TravelPlanner 的仓库规则专门限制测试查询结构化优化等做法，同时允许依许可构建扩展任务；TripCraft 数据需要申请并限制再分发；TravelBench 涉及用户、工具模拟和模型评价。它们适合作为候选来源，但当前包不能证明任何一个可直接容纳本方法并产生可比较榜单分数。PTS 所供 README 主要说明 RealTravel 数据，不能据此认定已拿到完整求解方法的可运行基线。

这一点暂列非阻断。方案阶段可选择一个窄受控问题，无须同时复现所有外部系统；但若一直只在作者构造的小型药房任务上调整，读者获得的可能只是某个接口的提示经验，而不是可迁移结论。

**Resolution test** 为最终保留问题选择一个有明确映射理由的外部任务来源，核实所需原始字段、许可、评分域和模型输入。如果只能做派生子任务，明确命名为派生协议并保留原任务分布与选择规则，避免写成官方复现。也可用独立构造、审核过的规则族验证边界，但须解释其覆盖的真实失败类型，而非为了降低强基线成绩而增加难度。

## 建议姿态与证据限制

支持暂停当前计算事实复核扩量，先收敛可区分的研究问题与外部任务映射，再决定是否投入正式实验。暂不支持进入以 DARC 独特收益为中心的论文写作，也不建议仅为延续项目而给后续 DSL 换一个方法名称。可信的负结果或边界研究仍可能具有 EI 会议价值，但需要比现有开发诊断更稳定、可迁移的证据。

本报告没有验证外部最新榜单、会议收录状态或文献全覆盖。原始请求、完整提示版本、样本语义审核记录和历史 v5.1 三轮实验底层结果不在所阅材料中，因此没有作独立复现实验声明。四份摘要是开发或事后诊断，不能据重复调用数推断独立样本量，也不能把“不见稳定收益”写成统计等效。未见证据不自动等于存在造假、泄漏或伦理问题。本报告完成后冻结，不依据其他意见调整。
