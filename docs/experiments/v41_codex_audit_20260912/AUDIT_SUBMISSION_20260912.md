## 5. 核心缺陷、反例与质量代价深度剖析

### 5.1 典型改坏案例剖析：`e2_clean_028_v0`

```json
{
  "utterance_id": "e2_clean_028_v0",
  "text": "Today, you'll be visiting the library, the bank, and the shopping mall. Make sure to focus on an efficient route to get through these locations quickly. Start your day by heading to the library before the bank to ensure everything goes smoothly.",
  "gold_intent": {
    "pois": ["bank", "library", "shopping_mall"],
    "dependencies": [["library", "bank"]],
    "quality_weight": 0.25
  },
  "candidate_A": {
    "pois": ["bank", "library", "shopping_mall"],
    "dependencies": [["library", "bank"]],
    "quality_weight": 0.0
  },
  "candidate_B": {
    "pois": ["bank", "library", "shopping_mall"],
    "dependencies": [["library", "bank"]],
    "quality_weight": 0.3
  },
  "review_response": {
    "pois": ["shopping_mall", "supermarket"],
    "dependencies": [],
    "quality_weight": 0.3,
    "evidence": {
      "pois": "Today, you'll be visiting the library, the bank, and the shopping mall."
    }
  }
}
```

- **事实过程**:
  1. Candidate A 正确识别全部目标 POI（bank, library, shopping_mall）与依赖，路径求解合法且满足所有约束，**任务判定为成功（Task Success = True）**。
  2. Candidate B 同样正确，仅权重与 A 存在微小分歧（0.0 vs 0.3）。
  3. 效用门控计算得出 $\Delta u = 0.0279 > 0.02$，触发复核。
  4. 复核调用虽然在 evidence 字段完整引用了原文指令，但在最终 pois 输出中**凭空幻觉出 `supermarket`，并遗漏了 `library` 和 `bank`**！
  5. 求解器依据复核意图生成的路线无法覆盖用户真实需要的地点，**任务失败（Task Success = False）**。
- **学术意义**:
  这证明 LLM 仲裁复核并非单调单向上升的“修正器”。在边缘歧义不明显时，过度调用复核反而可能破坏已经正确的初解。必须将“稳定性增益”与“改坏代价”并列呈现。

### 5.2 Gemini 124 次回退的技术归因
Gemini-3.1-flash-lite 的 Review Prompt 返回了带 Markdown 代码块的文本，并附带了尾部自然语言：
```markdown
```json
{
  "pois": ["supermarket", "library"],
  "time_limit": 1260,
  "dependencies": [["supermarket", "library"]],
  "quality_weight": 0.2
}
```

**Evidence:**
* "supermarket and the library"
...
```
由于当前评测契约执行严格的标准 `json.loads` 解析，反序列化时报错 `json.decoder.JSONDecodeError: Extra data`。当前 runner 不静默修剪文本，而是如实判定为无效候选并降级回退至 A。该回退机制保护了系统的鲁棒性，但绝不能将其等同于大模型复核生效。
