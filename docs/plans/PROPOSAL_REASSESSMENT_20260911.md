# Proposal 重新定位与下一阶段研究边界

日期 2026-09-11。状态为候选研究方案，尚未冻结为 v6，不是论文草稿。依据为[三份独立评审及综合意见](../experiments/task_audit_20260911/REVIEW_SYNTHESIS.md)和[公开任务审计](../experiments/task_audit_20260911/TASK_AUDIT.md)。

## 对现有 proposal 的判断

问题有意义，但目前证据不足以支撑以 DARC 性能提升为中心的方法论文。根本弱点是研究问题、实际实现与证明指标没有完全对应，而不是题目必须变得更大。

| 版本 | 研究对象 | 目前可得结论 |
|---|---|---|
| 历史 v5.1 | 两候选意图、交叉规划和字段替换后果、一次原句复核 | 精确方法尚无完整确认性证据；后续三字段实验不能代替其验证或否证 |
| Scene/Fair30 | 三字段规则、一个候选、场景事实表辅助复核 | 公平对照与接口诊断没有建立额外任务收益，停止当前实现扩量 |
| 本次候选 | 公开旅行任务中，语义忠实性与行程通过率的错位 | 尚待任务映射和强基线核验，不预设新方法胜出 |

Fair30 的语言/证据任务成功为 59/60、57/60；接口澄清后两组均 29/30，规则正确分别 25/30、27/30。因此不能说计算证据在任何指标都没用，也不能凭 2 个规则正确差异就宣称稳定增量。60 是 30 例两次重复，120 是 30 例四条件调用。这些均为开发证据。

## 候选题目、问题、方法与 benchmark

**候选中文题目** 自然语言旅行规划中的语义忠实性与任务成功失配评估

**候选英文题目** Evaluating Semantic Fidelity Beyond Task Success in Language-Based Travel Planning

这个题目以要测清楚的问题为中心，不预先宣称复核有效。DARC-Route 暂保留项目代号，不将它包装为已经成立的新算法。

**研究问题** 在同一用户要求下，基线系统生成的行程即使通过当前环境评价，是否仍包含语义误读；这些误读在预先定义、保持用户要求不变的环境变化下，是否造成可重复的任务损失？若存在，充分解释接口的语言复核和计算后果复核各能纠正多少、又改坏多少？

**核心技术对象** 首先是一套语义与任务联合评估协议。固定自然语言输入、显式预测约束和既有规划后端，分别检查约束忠实、行程可执行和跨环境表现。计算后果复核只是待检验干预，不是本次已认证的新方法。若任务审计表明标准基线没有相应语义错误，则不继续此方向。

**候选主 benchmark** ChinaTravel 原始自然语言模式。官方将普通 query 输入与开放标注 DSL 的 oracle_translation 区分，适合明确语义解析与后端求解的权限边界。[官方代码](https://github.com/LAMDA-NeSy/ChinaTravel)。只有完整安装及核验评分器后才能锁定。TravelPlanner train 可先用于工程核验；完整 TravelPlanner 验证属于后续可选范围。

**扩展协议的名称与边界** 环境配对变化是本项目派生诊断，不能冒充 ChinaTravel 官方榜单。公开原任务保持不变，官方分数与扩展分数分表。预先规定何种查询允许改变环境、怎样处理城市/实体绑定、何时 gold 要重新确认。确实改变了用户要求的样例不能算“语义保持”。

## 别人做了什么，我们还可能新增什么

已有 LLMAP/PTS 将语言解析与规划结合；形式化求解工作已在 TravelPlanner 上取得高约束成功率并处理不可满足原因；ChinaTravel 提供组合约束评价；FlexTravelBench 已研究约束更新；CORAL 的公开仓库也主张原始查询解析与局部修复。具体来源与复现边界见任务审计。因此一般的“调用求解器”“增加复核”“局部修复”“多轮保持约束”均不能直接列为本项目原创。

潜在新增知识是量化 **当前行程成功掩盖了多少语义错误，以及它们在合理环境变化下造成多少损失**，并判断反馈的信息增量是否真的修复这些错误。其价值是帮助研究者选对指标、避免把求解器成功误当接口忠实，也帮助系统设计者决定是否值得增加复核。

这个缺口仍需对最近工作的正文、指标和代码进行精确对照。此次定向审计只能证明一般框架已有先例，不能认证上述诊断从未有人做过。如果近邻已完整回答，则进一步缩小问题或停止，不靠重新命名建立创新。

## 实验应该如何设计

先复现同信息条件的强基线，至少包括充分定义的语言解析＋既有规划器。不能只与旧弱模型纯语言规划结果比较。选择兼容任务的公开方法后记录改动，不能把自写简化版本直接冠以原方法名。

若基线确实存在目标错误，冻结同一初始候选和后端，在相同复核机会下比较语言复核与计算后果复核。先单模型验证信息干预，再用第二模型检验结论可迁移性。供应商返回的模型名称和实际可观察配置如实记载，不把代理节点名称当架构证明。

| 指标 | 分母与解释 | 对应主张 |
|---|---|---|
| 官方 all-pass | 固定分区全部预期查询，缺失输出计失败 | 与同场基线任务表现比较；报告绝对百分点差 |
| 语义忠实率 | 有可靠语义标注的完整审核子集；不同但等义 DSL 不按字符串误判 | 自然语言解释是否正确，不能称已有官方指标 |
| 成功但语义错误率 | 全部审核任务为主分母，另报在成功任务中的条件比例 | 行程成功对误读的遮蔽程度 |
| 跨环境保持/损失 | 事先冻结的配对任务全体，按母查询聚类 | 语义错误是否有实际后果；派生协议单独报告 |
| 纠正、改坏及净纠正 | 同一候选上的成对结果，规则和任务分别统计 | 复核到底增加了什么信息价值 |
| raw/final、失败、成本 | 原始输出与回退后输出分列；总请求、重试、token、未知 usage、延迟 | 回退不能算模型修复；等调用不等于等费用 |

gold DSL 只在独立评分流程可见。模型只见原句、公开环境和自己生成的约束；从 gold 评分器取得逐条纠错建议也是 oracle 信息，不能偷偷作为方法反馈。已给 gold DSL 的后端成绩单列为诊断上限。

按母查询/意图家族划分开发与确认数据，表达变体、图变体和重复调用不可跨区。样本规模根据小批次错误率与区间精度设计；不在同一开发集上追求显著性。未被调用失败或方法成绩驱动的排除标准提前记录，所有最终指标保留完整分母。

不新增学习式门控、人工哈希参数或成绩驱动的路由阈值。哈希仅用于资产完整性，随机种子仅用于复现。是否进入下一阶段是研究管理判断，不是待发表算法的一部分。

## 为什么这版更可行

它把当前实验揭示的指标错位作为待检验问题，避免先命名方法再寻找有利数据。公开任务给出实际应用约束与比较接口；派生评估单独标识，避免伪榜单。先运行强基线和评分器，再决定干预与规模，可以在较小投入下判断是否还有研究空间。

它也存在明确风险。官方 DSL 未必完整表达语义；公开任务可能主要难在搜索和检索；环境变化可能破坏原句含义；近邻工作可能已覆盖相同诊断。任何一项都可能让候选不能成立。所以当前动作是完成任务可执行核验，而不是马上再跑数百次调用。
