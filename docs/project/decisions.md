# 关键决策日志 (Decisions Log)

本文档记录 DARC-Route 项目的重要架构演进与方法权衡决策，作为唯一的决策溯源点。

---

## 2026-09-05 DARC-Route v4 确定 EI 会议定位与最小闭环边界
- **背景**：v3 方案范围过大，包含了复杂的 Arbiter 训练、多场景外推和大规模长尾实验，执行风险高且缺少清晰预算控制。
- **决定**：收敛为面向 CCEAI 2027（EI Compendex）的可执行实证论文方案；聚焦于“有限复核预算下，利用规划效用差异能否改善复核调用效率”这一核心问题。
- **理由**：
  1. 范围紧凑、控制严格的 EI 论文胜过架构庞大但无法按期完成的计划；
  2. 6 周时间窗口与单一主研究者资源更契合清晰的受控实验设计。

## 2026-09-05 路线规划后端采用固定受控小图与精确枚举求解器
- **背景**：LLMAP 原开源代码中 MSGS 规划器缺少完整的真实场景地理数据与中间依赖，源码中包含负边权搜索与不透明早停机制。
- **决定**：主实验不依赖原 MSGS 代码，改为构建**固定小型合成 POI 图**（10 个 POI，5 类各 2 个，非空路线总数 6,331 条），采用纯 Python 精确枚举/剪枝求解器。
- **理由**：
  1. 保证所有方法在绝对公平、数学可解释、全局最优可验证的后端下对比；
  2. 单次求解毫秒级完成，大幅降低计算复杂度，彻底规避商业求解器依赖和求解器自身 bug。

## 2026-09-05 门控规则确立为双候选结构保护 + 效用差异触发
- **背景**：v3 方案中存在三次候选生成（含规范化文本）、复杂的连续风险指数与 top-2 margin 计算，门控参数过多且难以收敛。
- **决定**：
  1. 生成端由三次调用简化为两次：Prompt A（直接结构化提取）与 Prompt B（逐字段证据提示）；
  2. 门控采用分层结构：**结构/状态分歧强制复核**；若结构一致且有解，仅看候选路线在彼此预测权重下的最大效用差异 $\Delta_U > \tau$；
  3. 最多触发 1 次原句证据复核，且复核器**只看原句与分歧，不看候选路线**。
- **理由**：
  1. 基础推理调用从 3 次降低为 2 次，显著降低门控本身开销；
  2. 清晰隔离“规划决定是否花钱复核”与“语言决定用户真实意图”，避免规划端向复核器泄露标签或循环打分。

## 2026-09-05 数据集构建确立为 HIPP-Robust 200 组等义扩展与双人核验
- **背景**：原 HIPP 虽有 1,000 条数据，但存在大量近重复，且缺少成对等义扰动来衡量语言鲁棒性。
- **决定**：
  1. 严格语义聚类去重后抽取 200 个独立意图，每组构建 4 句（原句 + 3 个改写），总计 800 句；
  2. 划分 Dev（40 组/160 句，含 20 组 pilot）与 Test（160 组/640 句，完全冻结）；
  3. 引入双人审核机制（A 全审，B 独立复核 25% 及争议项），确保语义漂移率 < 5%。
- **理由**：
  1. 800 句数据规模既满足会议实证统计检验的样本量（配对 Bootstrap 功效），又在人工核验的可承受工作量之内；
  2. 冻结划分彻底避免门控参数向测试集过拟合。

## 2026-09-05 设立 Gate A/B/C 三级准入机制防止盲目扩量
- **背景**：若基础模型本身解析准确率过高（无错误），或复核器无法纠错，门控实验将失去验证基础。
- **决定**：
  - **Gate A（第 1 周末）**：20 组 Pilot 上基线确有任务错误，且始终复核产生“净纠错”，否则暂停扩量调整提示词；
  - **Gate B（第 3 周末）**：开发集上确认效用差异信号 $\Delta_U$ 存在且相比纯硬约束门控能带来有效区分增量；
  - **Gate C（第 4 周末）**：正式测试集上相对始终复核 TSR 损失不超过 2 个百分点，Token 节省至少 15%，且优于同预算随机和表示门控。
- **理由**：以清晰的 Go/No-Go 规则阻断无效假设，保障研究投入的确定性。


## 2026-09-06 实测环境与开发原句试跑
- **背景**：任务清单中的完成状态缺少独立可运行环境及部分关键边界检查；公开依赖别名可能导致约束失效。
- **决定**：建立核心目录 `.venv`（Python 3.12.13）和锁定依赖；使用标准库 schema 与独立 gold 检查器，修复未知 POI、空请求时间检查和依赖别名；25 项测试通过。
- **实验**：现有 FHL / gpt-5.4-mini 配置下完成 20 条开发原句 A/B/复核试跑。首轮 1 条传输失败，单独补测保留历史；60 次有效响应，1 次失败。两方法在可完成调用的原句上均满足参考任务，无净纠错。
- **边界**：不宣称 Gate A 通过，不把合成权重方向当作人工真值；80 句等义组与正式数据划分仍待完成。依赖标签簇仍为 609，但这是合成标签分组。
- **校正历史用语**：候选路线为 6,330 条非空＋1 条直达；精确后端仍需要测试，并非天然免疫 bug；5% 是扩大人工复核的触发值，不是允许的残余错误率。
- **证据**：`docs/experiments/readiness_20260906.md` 与核心目录 `results/readiness_20260906.json`。

## 2026-09-06 P0/P1 工程准备与数据交付闭环
- **背景**：指导书要求严格的数据无泄漏隔离、全套基线与门控实现、统一 CLI 接口及独立人工审核材料。
- **决定**：
  1. **效用未舍入浮点精度落地**：在 `RouteResult` 中增加 `raw_utility: float`，规划与门控统一采用双精度浮点比较（1e-9 容差），避免因提前舍入影响门控边界；
  2. **决策门控与基线实现**：在 `src/gating.py` 实现结构保护 $h$ 与交叉效用差异 $\Delta_U$，实现 B0—B6 全部基线，确保 B2 与 B0 逐例输出一致；
  3. **数据隔离与无泄漏划分**：提取 28 个开发暴露 source index；划分 200 组候选（Dev 40 / Test 160，包含 1 类 POI 场景，验证 0 cluster / 0 index 跨 split 泄漏）；
  4. **80 句等义候选与审核材料**：为 20 组 Pilot 构建 V0-V3 4 变体（共 80 句），交付 fillable 审核表；明确标记状态为 `pending_human_verification`，将正式 Gate A Pilot 标为 `blocked_on_annotation`，绝不以 AI 伪造人工真值；
  5. **统一实验接口与离线重算**：实现 `scripts/experiment.py`（9 大子命令覆盖），42 项测试全部通过，支持单条命令离线完整重算。
- **证据**：`docs/experiments/HANDOFF_RESULTS.md`、`docs/experiments/ACCEPTANCE_CHECKLIST.md` 及根目录 `submission_manifest.json`。
