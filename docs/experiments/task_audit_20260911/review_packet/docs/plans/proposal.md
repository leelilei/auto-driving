## 1. 题目、问题、方法与 benchmark

**中文题目：DARC-Route：面向自然语言 POI 路线规划的决策对比证据复核**

**英文题目：DARC-Route: Decision-Contrastive Verification for Language-Based POI Route Planning**

DARC-Route 保留为项目代号，不为旧缩写强行添加未经验证的理论含义。POI 指兴趣点，例如银行、药店和图书馆。

| 必须明确的问题 | 本方案的回答 |
|---|---|
| 我们研究什么？ | 在相同的一次复核机会下，显式呈现不同语言解释的规划后果，能否帮助模型纠正影响决策的误读，同时避免把用户本来合理的偏好改坏？ |
| 核心方法是什么？ | 两个候选意图、精确求解器生成的决策对比报告、一次回到原句证据的定向复核。核心干预是复核所获得的信息，不是决定是否调用模型的门控分数。 |
| 基于什么公开 benchmark？ | 基于 **LLMAP 的 HIPP 数据集**提供的指令与标签，构建本项目扩展 **HIPP-DC（HIPP Decision-Contrast）**。HIPP 是公开来源；HIPP-DC 是待建设的受控评测协议，不冒充已有公认榜单。 |
| 最终要量化什么？ | 相对同条件既有方法，任务满足提高多少个百分点、决策损失降低多少、每100个任务多纠正/少改坏多少，以及新增token和延迟；完整表格见§9.4。 |
| 我们预期新增什么？ | 一种可复现的候选解释—决策后果对比方法，以及同一意图跨图条件的配对实验，检验复核信息何时有用、何时无用或有害。 |
| 什么不作为贡献？ | 哈希、样本编号、随机种子、阈值调优、API 调度、单纯增加模型数量，以及“首次使用规划工具/反馈/复核”。 |

本研究从 v4 的“何时追加复核”转向“同样追加一次推理，什么证据使它有用”。这是研究对象的实质调整，不只是换标题。暂不承诺减少总 token；先证明复核的质量增量，再讨论效率。

## 2. 为什么值得研究

自然语言到规划有两层正确性。一层是求解器是否满足给定的约束；另一层是这些约束是否忠实表达用户的要求。求解器可以把一个错误解释优化得很好，但那仍然是错误任务的好解。

例如用户说“先去银行再去药店，尽量少绕路”。两个解析可能只在先后依赖或偏好方向上不同。在一个图中，银行本来就在去药店的路上，遗漏依赖暂时不改变路线；换一个地点布局，同样的遗漏会改变行程。反过来，两个权重数值差很多，也可能选出同一条路线。这里的例子仅说明拟研究机制，不是实验结果。

因此，参数差异、路线变化、实际任务损失不能等同。复核还有第四个问题：看到问题后，模型是否能纠正，还是会改变原本正确的理解？单纯报告 Route Flip 下降回答不了这些问题。

本研究的用途是改善自然语言接口与规划器之间的复核过程。若决策对比报告有效，系统可以用可计算的后果帮助模型定位需要回看原句的字段；若无效或诱发偏好漂移，也能明确这类反馈的适用边界。适用读者是语言接口、AI 规划与工具增强推理研究者，不是车辆控制或真实道路安全研究者。

## 3. 现有基础：别人做了什么，我们还需要做什么

以下是定向核查后的研究定位，不是穷尽检索，也不声称全球无人研究过相似方法。

| 已有工作 | 已完成的内容 | 对本研究的启发及不能冒领的部分 | 我们拟检验的具体区别 |
|---|---|---|---|
| LLMAP | 用 LLM 解析任务与偏好，连接 MSGS 路线求解；公开 HIPP；原文也观察到偏好权重识别的不确定性 | 自然语言到多目标 POI 规划与偏好不确定现象已有基础，不能把它们作为我们的发现 | 固定解析候选，改变图条件与复核信息，测量“解释差异如何影响路线、对比证据能否改善误读” [1] |
| 路线推荐 RouteLLM | 分层 agent 协作、全局约束验证、候选路线整合与对比解释 | 路线验证和替代路线说明已有；不能声称首次比较路线 | 我们把可计算的候选解释后果送回意图复核，并隔离其相对于字段差异及通用约束反馈的增量；不声称替代其完整系统 [2] |
| Smart Predict, then Optimize（SPO） | 用优化问题结构定义与学习决策相关损失 | 预测误差不等于决策误差不是新理论 | 我们不训练预测模型或可微求解器，研究固定模型推理时获得什么复核信息 [3] |
| CRITIC | 用工具反馈评价并修订模型输出 | “工具增强自我修正”已有 | 我们拟测试成对解释的可计算后果，而不仅是单个输出的通用工具反馈；必须设置对应对照 [4] |
| LLM-Modulo | 讨论模型与外部批评器、验证器的紧密结合 | 外部验证器参与规划不是新框架 | 我们的窄增量是自然语言意图层的候选对比证据及其同图/跨图控制实验 [5] |
| Key Condition Verification | 对关键条件进行验证，研究自修正能力 | 定向检查条件也不是新思想 | 必须比较“仅指出分歧字段”与“再给出其决策后果”，否则不能证明规划模块有必要 [6] |
| PlanGEN、2026 年符号反馈自修正工作 | 约束/验证反馈驱动规划细化，部分使用迭代机制或算法选择 | 相关方向仍在推进；不能以笼统的“反馈闭环”主张新颖性 | 本项目采用固定一次复核，检验紧凑对比报告的作用，而不靠更多迭代获得提升 [7][8] |

关于自修正，已有研究发现缺乏外部反馈时可能无法改善推理，甚至改坏结果；其他工作又在特定条件验证方式下取得改善。两者提示我们必须检验反馈内容和任务条件，不能预设“再问一遍一定更好”，也不能推断“所有自修正都无效”。[6][9]

**我们与上述基础的关系**：复用已有语言任务和可验证规划思想；提出一个具体的复核信息干预；用公平对照检验其净收益和失效条件。若字段差异反馈就能达到相同效果，应承认规划对比报告没有额外价值，不能靠重新命名获得创新。

## 4. 研究问题与可否定假设

| 问题 | 待检验假设 | 对应证据 | 否定条件 |
|---|---|---|---|
| RQ1（条件检查与机制分层）：同一解释分歧何时影响决策？ | 固定语言与候选后，改变图的质量—距离取舍及时间余量，会改变该分歧的后果 | 同一组候选在预设图条件下的可行性、路线和效用变化 | 变化主要由无关图差异或 tie-breaking 造成，或没有可测影响 |
| RQ2：决策对比证据能否提高复核质量？ | 相比相同调用次数的字段差异复核，加入真实后果能降低校准决策损失且不牺牲任务满足 | 主对比、双侧成功子集 regret、全样本失败、原句证据正确性 | 不优于字段差异对照，或收益来自 token/提示结构差异，或任务满足恶化 |
| RQ3：收益是否来自对比信息而非重复推理？ | 无后果报告、仅交叉约束反馈、错配报告会削弱效果 | 去模块、通用工具反馈、预设错配干预及报告长度分层 | 替代输入同样有效，或正确报告反而诱导偏好漂移 |

RQ1 用于验证评测条件和划分机制，图改变优化后果本身不是新的理论发现；主要研究增量取决于 RQ2 的净纠正证据和 RQ3 的对照结果。

所有假设都可能失败。历史结果中的 Flip 改善与 regret 恶化只能作为动机和开发诊断，不能作为 v5 正面证据。

## 5. 核心方法：决策对比证据复核

### 5.1 输入、输出与固定流程

输入是自然语言指令 x 和冻结图 G。意图接口仍为 y=(S,T,D,w)，分别表示 POI 类别、截止时间、先后依赖、质量权重。图中的地点坐标、开放时间和停留时长来自场景。

流程如下。

1. **产生候选 A/B**。固定模型分别用直接解析提示和带原文证据的解析提示读取 x，二者不互看输出。保留完整结构与原文片段，严格 schema 检查。
2. **构造决策对比报告 E**。固定求解器在 A、B 各自要求下求路线，并对两条路线交叉检查。再做有限的单字段替换诊断，说明哪个分歧与可行性、地点选择、顺序或质量—距离取舍有关。
3. **一次原句证据复核**。复核器输入 x、A、B、E，输出完整意图及修改字段的原句依据。它必须判断原句支持哪种理解，而不是替用户选择看上去更高效的目标。
4. **重新求解与独立评价**。生产求解只接收最终预测；gold 仅由离线评价器使用。输出错误、不可行、缺失均保留，按预先规则计入失败。

主方法固定 **A+B+一次复核，共三次 LLM 调用**。所有样本都有相同复核机会，包括两候选相同的样本。没有“风险超过 τ 才复核”，没有基于 ID 或哈希决定采用哪份答案。若候选相同，报告如实显示未发现候选差异，不能把这当作正确证明。

### 5.2 对比报告怎么生成

报告由代码生成，不再多调用一个 LLM 编写反馈。所有类别/节点字段按固定、公开的顺序序列化。每份报告包含：

| 内容 | 可计算含义 | 禁止解释 |
|---|---|---|
| 候选字段差异 | S/T/D/w 的差异与两个候选提供的原文片段 | 不把任一候选片段自动当真 |
| 两条路线及原始属性 | 地点顺序、覆盖、距离、时间、平均质量 | 不按某个预测权重的高分认定用户意图正确 |
| 交叉约束检查 | r_A 是否满足 A/B，r_B 是否满足 A/B；具体违反的预测约束 | 不声称满足候选就满足真实用户要求 |
| 单字段替换后果 | 仅替换一个不同字段后，路线/可行性如何变化 | 不称为真实世界因果效应或用户偏好证明 |
| 未覆盖的情况 | 候选无效、共同误读可能、多个字段相互作用 | 不把“未发现差异”当作“无需检查” |

单字段诊断对 S/T/D/w 四个字段块分别进行双向替换，即 A 的一个字段换为 B 对应字段，及 B 换为 A。最多新增 8 次小图求解；加上原 A/B 最多 10 次，最终意图最多再求解一次。字段相同则不做该替换。替换后 schema 非法或无解时记录原因，不偷偷修补；复核器也不被限制为只能选择这些混合候选。多个字段共同改变的整体后果由原 A/B 对比提供；单字段诊断不能完整识别高阶交互，作为限制披露。

报告给出原始物理属性与可行性，不输出“请选择 A/B”或“真实错误概率”。连续数值的显示精度与求解数值容差只是工程约定，不能拿来划分语义重要性。记录精确最优解是否存在并列，避免把稳定 ID 平局规则造成的路线变化解释为有意义的损失。

### 5.3 为什么这种信息可能有用

普通复核只告诉模型“再检查一下”；字段差异复核告诉它“两份答案哪里不同”；本方法进一步告诉它“这些不同在当前任务中分别意味着什么”。可检验的机制是，具体后果帮助模型把注意力定位到有决策影响的原句条款，再据原句修正误读。

更准确地说，后果呈现可能改善模型对已有语言证据的利用，而不是提供新的用户意图信息。对不依赖图的明确指令，正确语义在三图间应保持一致；分别统计硬约束与偏好方向的跨图保持率，避免把受图诱导的语义漂移误当作合理适应。不同路线可以合理，随图擅自改变用户要求则不合理。

这仍是待检验解释。图不能生成用户未说过的信息。“质量优先”没有唯一数值权重时，复核不能凭路线看起来好就宣称恢复了真实 w；人工评价中的不明确偏好标为 unclear，独立报告，不以反复采样强行消除歧义。unclear 是评价标签，不是本版数值 w 接口的新输出值：各方法仍按自己预测的数值 w 求解，但该数值不能被称为已恢复的真实偏好；unclear 不参加方向准确率和校准 regret，仍参加硬约束与歧义诊断。本版不新增弃答动作。候选共同犯错、原句缺乏信息、对比报告误导，均可能导致方法无效。

### 5.4 输出约束与失败处理

复核必须返回完整 S/T/D/w，以及变更字段和支持变更的原句片段。字面片段存在可由代码检查，但证据是否真正支持修改需独立评价，不能把字符串匹配当语义正确。

复核结构无效则依次回退有效 A、有效 B，否则解析失败；最终规划无解则保留失败，不放宽原句硬约束。对照方法采用相同规则。网络重试策略、输出长度上限、缓存记录是实验工程参数，不作为方法贡献。

## 6. 门控、哈希和参数的使用原则

- **主方法不采用选择性门控**。v4 的 h∨ΔU>τ 只保留为历史/可选对照，不作为 v5 的创新主线。未来只有在复核净收益已成立、部署确有预算需求时才另立选择性调度研究。
- **哈希不进入任何模型或决策规则**。SHA256 仅验证文件与缓存内容，不能充当风险分数、参数、样本选择特征、模型输入或答案选择依据。
- 随机对照如需抽样，用预先固定的常规伪随机种子，保存实际抽样清单；不得搜索“效果最好”的种子。随机性属于实验控制，不属于核心算法。
- w 是任务模型已有的可解释偏好接口；w_eval 是公开的评价假设。两者不能与无物理含义的风险系数混淆。保留映射敏感性，避免只挑一种权重规则。
- 固定字段数、图规模、解码上限等参数必须写清计算/资源作用。不会新增可学习门控、多阈值组合、哈希参数或复杂融合分数来补足研究叙述。
- 项目“实验准入”是执行管理要求，与算法门控不同；实验未验收不得自动进入论文阶段。

## 7. Benchmark：HIPP 为基础，建设 HIPP-DC

### 7.1 公开基础和复用边界

HIPP 来自 LLMAP，原文附录 B.1 说明有 1,000 条样本，包含合成标签、对应指令与解析估计。[1] 本地原始文件是 `9-AutoDriving-core/data/raw/HIPP.json`，冻结提交为 `281f6ad95f42ca386400e5288f006aeffa2ac282`，SHA256 为 `5fd5101a9bdb93823f0fe4109fa5342d6bd7d45ef240498a2f822f0554efbf02`。[10]

我们复用语言任务来源，不把已有模型估计当新实验答案；也不称 HIPP 为真实用户行为日志。当前本地缺少复现原 MSGS 完整地图实验所需的全部场景依赖，因此采用可公开的受控图，不与原论文城市路线表直接比较数值。

### 7.2 HIPP-DC 的三个组成部分

| 部分 | 拟建设内容 | 回答的问题 |
|---|---|---|
| 语言层 | 意图组，每组 V0 原句和三个经审核的等义表达；另设最小真实语义变化对照 | 变化来自措辞还是用户意图？ |
| 场景层 | 同一意图配三个冻结图条件，精确求解；候选 A/B 在三图共享 | 同一解释分歧为何有时影响决策、有时不影响？ |
| 复核干预层 | 同候选、同图、同模型，改变第三次调用得到的反馈信息 | 改善来自重复推理、字段提示还是具体决策后果？ |

不另起一个与 HIPP 无关的大型数据集。HIPP-DC 是“来源指令＋审核改写＋图条件＋反馈干预”的评测层，文件和版本需要单独建设。

### 7.3 规模与划分

目标仍为 200 个独立语义意图组，开发 40 组（Pilot 20、校准/提示开发20），测试160组，每组4句。每个意图对应3个图条件，测试产生 160×4×3=1,920 个指令—图实例，但**独立意图数仍是160**，不能按1,920个独立样本计算统计显著性。

历史使用过的200组及其等价语义簇全部登记开发暴露。现有 `test_640_utterances_v2_confirmed.json` 即使重新采集也属于已暴露意图的新鲜复现集，不能直接作为 v5 未见确认测试。先审计 HIPP 剩余独立簇是否足够，再按预定规则建立新划分；不足160测试簇就如实调整规模和统计功效，不重复凑数。不保证这些公开指令未进入基础模型预训练，所说隔离仅指本项目开发过程。

划分前按原句支持的类别、截止时间、依赖及偏好含义建立语义簇，由机器提出重复候选、人工裁定边界；不单凭合成标签数值判定独立性。母句、改写及由其构造的最小语义变化对作为同一划分家族，禁止跨开发/测试。

人工判断先审 V0，再审改写；原合成标签、原句支持的硬约束、方向标签、评价权重分字段保存。负责人对14组修订的认可不能自动扩展为其他句子双人审核。A全审，B独立复核25%与争议项；如果团队选择不同审核方案，须事先改协议并如实披露，不代签。

### 7.4 三类图条件的构造原则

保留五类各两个 POI、固定速度、开放时间和停留时长、精确枚举后端。每组共享节点身份及基础几何布局。先生成宽松、gold 可行且存在不同距离完整路线的父场景，再冻结字段级变换，构造以下配对条件：

1. **同向条件**：固定父场景几何、时间与节点，只设置质量属性，使 gold 下存在同时达到最高质量和最短距离的完整可行路线。可在开发阶段使用所有节点等质量的明确退化控制；若采用该方式必须标记，不能把它描述成自然质量分布。用来研究权重差异何时无害。
2. **权衡条件**：从同一父场景出发，仅改变质量属性，保持几何、速度、停留与时间窗口不变，使完整可行路线的质量最大解集合与距离最小解集合不相交，至少存在两个不同的非支配解。质量赋值规则及搜索上限只在开发阶段确定。
3. **时间敏感条件**：以权衡图为明确父图，固定质量、几何、速度、停留和原句要求，仅收紧场景关闭时间，使完整可行路线集合缩小且非空；不修改或添加用户截止时间。

这些条件主要控制权重误读的质量—距离后果及时间可行性，不能推断同向图会消除 S/D 等硬约束误读。按 S/T/D/w 分歧类型分层，允许候选在某一图变换下完全不受影响，不要求每组 A/B 都翻转。

用结构属性和精确可行集检查上述条件，不运行 Ours 选择“效果最好”的图。具体坐标生成范围、时间余量构造和最多重采样次数在开发阶段确定并冻结，当前属于待实现配置，不宣称图文件已满足这些条件。失败的构造保留日志并报告失败率；自然分布之外的受控机制样本单独标记，不据其比例估计真实用户风险频率。构造可使用评测方 gold 检查可行性，但 gold、条件标签和构造元数据均不进入模型或反馈生成器；输入仅含正常场景属性。

### 7.5 语义变化与无歧义/歧义诊断

另建40个最小语义变化对，每对只改变一条时间、顺序或偏好要求；仅在语义确实要求决策改变的子集检查响应适当性，并要求双侧任务满足。无明确偏好方向的样本在人工评价中标 unclear，不把预测数值或默认0.5当作中立真值；保留其硬约束评价并单列歧义分析。

## 8. 对照与消融：证明我们新增的信息有用

| 方法 | LLM输入/调用 | 作用 |
|---|---|---|
| 单次 A | 一次直接解析 | 最低成本参考 |
| 三次自一致性 | A/A2/A3，完整候选 medoid | 多采样参考；是本任务适配，不冒充原论文完整复现 [11] |
| 普通复核 | A/B＋原句复核，共3次 | 与 v4 Always Review 对齐，隔离反复推理 |
| 字段差异复核 | A/B＋明确字段差异＋原文候选证据，共3次 | **主要比较对象**，检验求解器是否真的必要 |
| 交叉约束反馈复核 | 字段差异与证据＋r_A/r_B 对 A/B 的全部交叉约束检查，共3次；不提供质量/距离对比和字段替换后果 | 通用工具/符号反馈的本任务适配对照，不称 CRITIC/RouteLLM 原系统 |
| DARC-Route v5 | A/B＋完整决策对比报告＋原句证据复核，共3次 | 检验后果对比及字段替换诊断的增量 |

主方法与其他三种复核共享 A/B、图、模型、原句证据格式、输出要求和解码上限，均不能看 gold。交叉约束对照不能只验证路线满足自己的生成条件，那通常会退化为恒真报告。RQ3 中的约束反馈均指这里的完整交叉检查。第三次调用分别真实采集，不能复用普通复核输出冒充 v5 复核输出。

固定三次调用并不等于相同 token。逐方法报告输入/输出 token、失败/重试、端到端与求解耗时；开发阶段冻结长度匹配的字段反馈补充对照：仅展开原句片段与字段说明，不加入规划信息；按 tokenizer 的输入长度区间配对报告效果。不得用重复无意义填充冒充公平匹配；无法获得重叠长度区间时如实承认 token 混杂仍未排除。固定输出上限不是实际预算严格匹配，不能据此声称同成本占优。

最小消融：去掉单字段替换但保留整体 A/B 路线对比；去掉规划后果只保留字段差异。预设小规模错配报告诊断使用同节点模板另一图条件的报告，明确是受控错误反馈，不混入主集，不据“错配变差”单独证明正确证据有效。

## 9. 指标、统计与可接受结论

**主要比较是 v5 对字段差异复核，而不是只对单次 A。** 两个共同主要终点为任务满足 TSR 与共同成功实例上的条件性校准 regret，分别报告，不用任意加权总分掩盖权衡。

TSR 检查 gold 请求、时间、先后依赖和开放时间。v5 固定路线域：从给定起点到终点，每个 gold 请求类别恰好访问一个 POI，不访问额外类别，不重复访问；空请求只允许直达。部分覆盖、漏类别、多类别都不算成功。oracle 枚举必须与这个接受域完全一致，不能让实际路线参加更宽的比赛。此处是待落实的新评价约定，不声称旧检查器已经如此执行。

GTSR 要求同一意图在同图下四句全部成功。偏好方向准确率、原句证据支持率、改正/改坏数同时报告。证据支持率采用测试前冻结的分层抽样及分母：区分有修改和未修改输出，审核者只见原句、候选和待核查断言，不见方法名；A判读、B独立复核争议并记录仲裁，不能以引用片段存在代替语义支持。

对两方法都成功且方向明确的同一实例，以 gold 请求和预定 w_eval 求精确最优路线 r*，统一计算

`L(r) = [U_w_eval(r*) - U_w_eval(r)] / 2`，其中 `U_w(r)=w Q(r)-(1-w)D_bar(r)`。

Q 为所访 POI 的平均质量，节点质量范围[0,1]；空请求 Q=0。D_bar 为总路径距离除以 6×图最大边长，沿用最多五类、每类一次所形成的最多六段路线；同一图所有预测和 oracle 使用同一尺度，不能按候选各自归一化。零尺度图拒绝纳入测试。以上使 Q、D_bar 均在[0,1]，除以2仅为固定展示尺度，本版 L 的上界不超过0.5。

主映射0.75/0.50/0.25，敏感性0.65/0.50/0.35及0.85/0.50/0.15。它们是研究者公开设定的评价尺度，不代表恢复了用户真实精确偏好。显著负 regret 触发求解/评价错误检查，不静默截断；逐比较报告双方成功、仅本方法成功、仅对照成功、双方失败四格，附偏好/图条件分布。共同成功子集由方法结果决定，其 regret 改善不能单独证明全体任务净收益。另在所有方向明确的实例上将失败赋0.5、1、2分别做敏感性，成功用 L，明确这些惩罚是评价假设；结论若随惩罚改变，就报告权衡。unclear 不进入这项软偏好分析。

Route Flip 只作诊断，给出共同任务成功对的分母及并列最优情况；不能通过稳定地产生错误路线获得方法成功判定。

按独立语义簇分组，保留同簇全部表达和图条件做配对 bootstrap（10,000次，固定种子42），输出差值95%区间。差值统一为本方法减对照，TSR越大越好、L越小越好；完整终点先在簇内等权平均全部表达和图，再在簇间等权平均。共同成功 L 先平均各簇内合格实例，仅对有合格实例的簇取平均并报告实例/簇分母；重采样后无合格实例则记不可估计，不能填0。主要比较预定，其余正式多重比较用 Holm 校正；图条件和原句/改写分层标明探索性。预先选40个测试意图做两次额外端到端重复，每次重新采集 A/B 和各复核，单次重复内部仍共享 A/B，加原次共3次；不与仅重采复核的条件随机性混报，重复不增加独立意图数。

暂以 TSR 差值下界不低于 -0.02 作为拟议工程非劣容忍范围，需在新测试前结合任务容忍依据确认，不能当作已获负责人批准的标准；开发阶段还需确定最小有用 regret 改善及据此进行簇级功效/区间精度评估，当前160组只是目标而非已证明足够；同时主要 regret 差值区间应支持改善。若区间不足以支持，结论为不确定或权衡，而非“同等性能”。如只改进硬约束、不改善软偏好，允许按实际证据收窄贡献；若仅 Flip 下降而任务/效用恶化，则不判定方法有效。

### 9.5 哪些结果可以称最佳，什么时候才讨论SOTA

1. **当前可争取的主结论**：在HIPP-DC指定版本、模型与资源设置下，相比预定文献提示重跑和复核对照，任务表现提高多少、决策损失降低多少。满足预定统计标准后可说“优于这些基线”；并列或区间不支持则如实表述。
2. **扩展基准最佳**：覆盖合理的强基线并公开评测协议后，可称“所比较方法中最佳”或“该版本HIPP-DC上的最佳已评估结果”。自建数据/指标第一名本身不构成公认SOTA；跨指标有权衡就分别报告，不选一个有利列包装整体最优。
3. **外部benchmark某项SOTA**：需要冻结公认/公开既有任务的测试样本、标签、输入信息、评价器与资源轨道，复核截至报告日期的最强可复现成绩并遵守其规则。换模型、加图、改标签、改成功定义都要另列设置；不存在统一规则时不虚构一个排行榜。单次点估计第一也不等于统计证据充分。
4. **若外部SOTA成为硬目标**：另行完成原路线场景与评分协议的复现，或选择确实适配该方法的公开任务扩展验证；先做可复现性/资源评估，再冻结范围。当前不能靠给HIPP-DC换名实现这个目标。

本项目优先交付可信的“方法增量＋量化对照”证据。EI会议目标不预设必须获得全球SOTA，也不以放弃强基线来确保正结果；最终定位由实验决定。

## 10. 新方案为什么比 v4 更值得做

| v4 的风险 | v5 的实质改变 | 为什么更好、代价是什么 |
|---|---|---|
| 创新容易归结为替换门控分数 | 改变复核获得的信息，明确字段对照和工具反馈对照 | 可以直接检验新增模块是否必要；也可能被简单对照否定 |
| 决策分歧被当成追加复核价值 | 每句都有同样复核机会，直接测净纠正和净损失变化 | 不靠阈值选择隐藏改坏样本；放弃默认节省调用的卖点 |
| 方法主要改变软偏好，主指标却只看硬约束 | TSR与同尺度regret共同评价，Flip降为诊断 | 评价对齐实际机制；人审与映射敏感性工作仍不可省 |
| 不同语言样本和图差异混在一起 | 同意图、同候选、跨图条件配对 | 更容易解释环境何时放大误读；受控图不能冒充自然分布 |
| 易把求解器或反馈闭环包装成首创 | 明确承认LLMAP/RouteLLM/工具反馈/条件验证基础 | 增量更窄但可检查，降低夸大新颖性的风险 |
| 通过增加模型数量补证据 | 先主模型证实信息干预，再一个补充模型 | 把资源优先用于机制、对照和数据；不承诺五模型全量 |

新颖性仍有明确待办：检索已有“候选意图交叉规划＋字段替换后果＋一次语义复核”的近邻组合，并按具体反馈内容比较；仅凭已有方向的概览不能证明组合原创。

“更好”是指问题、方法、指标与证据更一致，不表示性能一定优于 v4，也不保证论文录用。

## 11. 可行性、成本与停止条件

先完成20组开发意图的审核，使用其中预先固定的8组做实现验证，再跑完整开发集。冻结候选、反馈协议和图构造后再决定测试规模，不在测试上反复修改报告格式。

按160组×4句×3图计算主模型核心实验：A/B在图之间共享需1,280次；四种复核信息各对1,920个实例调用一次需7,680次；自一致性新增A2/A3共1,280次，合计约**10,240次基础调用**。这比 v4 的3,200次主集调用更多，不能声称更省研究费用。开发、消融、对照变化和重复另行估算；先用 Pilot 实际 tokens 形成预算清单，若超预算先缩减额外模型/重复子集或经功效评估缩小规模，不删除主要字段差异对照。v5.1新增两种文献提示同模型重跑，若不能与已有A请求逐字一致复用，再加2×640=1,280次，核心基础预算调整为最多11,520次；V0历史解析重评分无需API，评分器核验也无需API。原始1000条上的新鲜全方法扩量不在这笔预算内，须单独估算。当前没有执行此预算。

停止条件：真实反馈无法稳定生成；原句证据经审核发现系统性漂移；在开发集相对字段差异复核没有净收益且一次有限提示修订后仍失败；对比信息诱导更高任务错误；新颖性核查发现方法与已有方法实质重复。满足时暂停扩量，保留负结果，重新审议问题，不用复杂门控或哈希策略补救。

## 12. 现有基础如何迁移

| 已有资产 | v5 处理 |
|---|---|
| Python环境、严格意图schema、精确求解器、独立检查器 | 复用并增加对比报告正确性和并列解测试 |
| HIPP原文件、来源索引、历史人审候选和暴露记录 | 保留；重新审计可用独立簇，不能把历史test当未见 |
| A/B解析、逐次调用记录与文件校验 | 复用；哈希仅为完整性校验 |
| v4门控与普通review | 保留为历史/对照，不当v5方法实现 |
| fresh-stage运行器 | 暂停扩量；需新增图条件、对比报告、分方法真实review与统计路径后才能用于v5 |
| 旧论文草稿 | 封存，不据其结论反推实验；不在本任务修改 |

按依赖顺序交付：数据资格与暴露审计 → 对比报告生成器及手算测试 → 8组诊断 → 20组Pilot/开发对照 → 冻结完整协议与预算 → 未见测试或明确标记的历史复现 → 独立验收 → 负责人认可 → 论文写作。阶段三的旧准入文件不能自动放行 v5。
