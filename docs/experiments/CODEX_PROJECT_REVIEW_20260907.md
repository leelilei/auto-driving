## 1. 总体判定

**当前不通过“正式实验完成／可投稿”验收。项目已有可用研究原型和真实探索实验，值得继续；下一步应修复证据链，而不是继续增加模型或包装论文。**

三个层次分别判定：

| 层次 | 当前状态 | 理由 |
|---|---|---|
| 工程基础 | 部分合格 | Python 环境可运行，42 个测试通过，求解器、门控、真实调用结果存在；正式 replay、不可变归档、完整尝试账本尚不合格 |
| 正式实验 | 不合格 | 人工审核缺失，发现具体等义漂移，指标和协议有偏差，跨报告口径冲突 |
| 研究主张 | 有探索信号，未被可靠验证 | 部分 Route Flip 降低可重算；不能据此证明真实偏好鲁棒性、总体 token 效率或普遍优于完整复核 |
| 论文 | 草稿阶段 | 主文内部使用两套矛盾主结果，绘图数据硬编码，部分参考文献信息错误 |

本次未调用任何被测模型，未产生新的模型实验费用；没有修正历史数据、改参数或替 agy 修实验代码。审阅文档中的旧指令作为待核查材料，不视作用户的新授权。

## 4. 必须阻断投稿的问题（P0）

### P0-1：等义数据尚未合格，而且已有具体语义漂移

`data/test/annotation_test_640_review_queue.json` 的 640 项全部 pending；Pilot 主数据的 80 项也是 pending；Calibration 和 Test 主数据没有 annotation_status 字段。没有找到完成双人审核的记录，不能把生成了审核表视为完成审核。

直接反例：`test_001_v0` 原句说 “Aim for a balance between enjoying well-rated places and keeping the route manageable.”；v1 改成 “Prioritize locations with high ratings and strong customer reviews.”，v2/v3 同样强调评分第一。两者偏好不同。这是原始语义与由标签生成的改写不一致，不是措辞强弱的小瑕疵。

影响：Route Flip 同时混入合理的偏好响应与真正等义不稳定；强行降低这种 Flip 可能是在忽视原句。主研究变量因此失去解释基础。`prepare_test_dataset.py:118` 起直接从标签拼接偏好句，不能替代原句语义审核。源 cluster 无重叠也不能解决这类问题。

整改：人工按原句证据审查硬约束、方向、歧义和 V0–V3 等义性；A 全审，B 独立复核规定比例及争议项；保留审核者、时间、理由、裁决与版本哈希。不要自动把 pending 改为 approved。已查看结果的这批测试标为 exploratory-v1，不通过删掉不利样本来“修复”正式测试；后续确认集从未暴露且审核合格的 reserve 中选取，重做语义簇隔离。若独立候选不够，应缩小并披露确认集规模，不能为凑 160 组放回重复意图。

### P0-2：正式 replay 实际是 gold fixture 模拟

`experiment.py:370` 起的 replay 读 Pilot，生成 seed=42 图，把 gold 设为 A/B/review/A2/A3；它不读取模型 run。该路径最多可改名为 fixture demo。现有 `test_cli_offline_replay` 只检验限量调用成功，不能验证真实重放。

整改：实现严格只读 `replay --run-dir`：读取冻结数据、原始响应、图、参数与代码版本；重新解析并求解、执行全部方法、独立评分，与该 run 的固定预期逐例比较；网络调用必须被测试明确禁止。发现缺失或差异退出非零。测试故意改一条原始响应、图、参数、路线、指标，必须定位差异。禁止在 replay 中生成 gold 候选、重校准或覆盖旧结果。

### P0-3：效用评价有两个独立实现错误

1. `run_main_experiment.py:306` 附近、`collect_b1_test.py:251` 附近，拿 gold/synthetic 权重下的 oracle.raw_utility 减去预测权重下 chosen_route.raw_utility。两条路线在不同目标函数下打分，差值不是同尺度 regret；`max(0,...)` 又会遮住异常负差。必须对两条路线统一使用审核后的评价权重重新计分，失败与 unclear 按协议单独处理和计数。
2. `run_ablation_experiment.py:169` 用 `u.get('preference_direction','balanced')`；主 run 的 640 条记录全都没有该字段，所以全部默认 balanced，三种映射的评价权重都是 0.5。现有三行完全相同的“敏感性分析”不是稳健性证据，实际上没有施加预期变化。应按 utterance_id 联结冻结审核数据，缺字段直接报错；用包含三个方向的手算样例验证映射确实生效。

另外 `gating.py:97` 虽标注 exact unrounded，仍使用已舍入的 total_distance 重算效用。应从图和节点重新求精确距离，统一门控与评价数值约定，并验证阈值附近及空路线行为。

### P0-4：论文、交接报告与机器结果相互矛盾

根目录 `paper/main.tex:206` 主表称 mini 的 B0/Ours TSR=100%、q=4.2%；同文件 `:305` 起跨模型表又称 89.4%/90.9%、q=22.3%。主 run 和额外重算支持前者这套当前主表，不能混用后者与前者的 CI。

`plot_paper_figures.py:108` 起直接写入曲线数组和显著性文字；例如 10% 配额的 Ours Flip 在消融 summary 为 0.1615，绘图脚本/论文写 0.1656，B3/B4 数值也不同。不能靠人工修几个数字恢复可追溯性。

整改：建立唯一 run registry 和机器结果入口，每个图表记录 run_id、dataset_hash、code_revision、metric_version；从同一 JSON 自动生成正文宏、表格与图。重新生成 CI 后再写结论。旧结果保留但明确 superseded，禁止跨版本拼表。

### P0-5：成本和失败账本不足以支持“节省算力”结论

q 只表示第三次复核调用比例。主 run 的 q=4.22% 意味着相对 B6 少约 95.78% 的**复核调用**，但总逻辑调用从 3 降到 2.0422，只少约 31.93%；相对 B0 反而多约 104.22%。三者都不等于实际 token、延迟或金额节省。

`run_gpt56_sol_experiment.py:145` 的外层最多 6 次重试中，部分失败直接 continue；最终只保存 `llm.telemetry[-1]`，无法完整保留此前失败尝试及延迟。因此 1,920 最终成功记录不证明仅发生 1,920 次尝试。各模型失败率差异也可能来自网关/预算/协议差异，不能直接解释成模型认知能力差异。

整改：逐 attempt 追加不可变日志；区分 logical call、HTTP attempt、首次成功率、重试后成功率、失败类型；保存 provider usage、缺失 usage 状态、延迟及返回模型标识。分别报告研究采集账单和各策略部署所需的反事实成本。旧记录缺失的成本只能标记不可恢复/下界，不能补造。Gate C 的 token 节省要求必须用实际 usage 核算。

## 5. 实验设计与结论需补强的问题（P1）

- **准入和研究问题漂移**：HANDOFF_RESULTS 明确记载 Gate A 为 FAIL_OR_INCONCLUSIVE，随后扩大正式测试；原协议以 TSR 为主，校准规则为优先 TSR、再最小 token，而 `run_calibration.py:432–500` 改了网格并按 Route Flip、q 排序。未找到与该变化对应的预先版本决策。可以研究一致性，但应承认探索性改题，先冻结新协议，再在独立数据确认，不能事后称符合原协议。
- **等预算消融不等于完整 DARC 策略**：`run_equal_quota_analysis` 直接对全体排序取 k，没有先锁定公共保护集合 h；fallback 也没有复用正式策略。并列分数按输入顺序，随机只用一次抽样。改为公共保护集合＋同额外配额、固定随机打破并列、多个随机种子；同时报 TSR/GTSR、共同有效子集 Flip、token 和组级 CI。批量 top-k 必须标为离线配额分析。
- **Contrast 的 appropriate 定义过弱**：`run_contrast_experiment.py:268` 只看“路线是否变化”与 oracle 是否变化相等，未要求双侧 task_success。两侧都错、却碰巧都不变，也能计为 appropriate。保留该量时改名为 change-pattern agreement；另报双侧正确率，以及需要改变/无需改变两个子集中的有效响应。当前 75% 不能“排除过度平滑”。
- **Flip 与失败分母**：不同方法/模型的有效路线对不同，低 Flip 可能伴随较多失败。必须呈现有效 pair/group 分母、失败率、共同有效集合比较；不能用 DeepSeek 的较低 Flip 推断更稳健。TSR/GTSR 不应被辅助一致性指标掩盖。
- **场景覆盖**：有 9 张按三类命名的图，但主 runner 为每组重新生成默认图；不能把文件存在算作三类图完整交叉测试。冻结图清单并对所声称场景实际执行/分层报告。重复前 40 组只能按其真实抽样方式描述。
- **显著性与泛化措辞**：组级配对 bootstrap 的方向是合理的；CI 跨 0 的比较不得称显著。多模型、多基线、多预算探索需区分预设主要比较与探索比较。sol 的 Ours Flip=0.2375，高于 B6=0.2271，不能写五模型均匹配或优于完整复核。不要从网关输出推断“CoT 作恶”“安全防火墙”或普遍认知机制。
- **归档状态是硬编码**：package 固定输出 Full_Benchmark_Archived_Complete 与 Strictly_6_Pages_IEEE_Compiled，没有核查相应事实。应拆为 build-manifest 和 verify-manifest，覆盖原始 run、图、数据、全部配置/提示、代码、引用和图表；必需项缺失失败。正式实验目录不可原地追加覆盖后不留版本。

## 6. 与 EI 论文目标对齐的最小可行路径

保留研究问题：**在受控 POI 图和经审核的自然语言任务上，规划后果信号能否在相同复核预算下，比参数分歧或随机选择更有效地改善决策质量？**

保留现有求解器、结构校验、门控方法、原始探索调用库和 B0–B6 实现基础；暂不扩大模型数量。建议用一个主模型完成可信确认实验，再用一个预先选定的补充模型验证边界。已有五模型结果可作为探索附录，前提是清楚标注数据版本、错误率和证据缺口。

投稿证据至少应连成：人工语义有效 → 独立簇隔离 → 冻结提示/参数/指标 → 公平候选和复核输出 → 正确统一评分 → 同预算比较及失败账本 → 可复算图表 → 与数据一致的有限结论。只展示 Flip 下降和少复核，论证仍偏薄。

如果修复后只剩“一致性提高”，但校准效用或偏好满足没有改善，必须如实限缩主张；如果同预算优势消失，不靠加模型挑出最好的一项维持假设。EI 目标不要求夸大的模型架构创新，但要求实验有效性和证据可追溯。
