# 研究问题调整说明：先验证场景条件解析，再决定是否保留复核方法

2026-09-10。目标仍为一篇EI会议研究论文。本文是研究决策与实验设计，不是论文正文。v5.1原稿保留为历史方法依据；当前暂缓按其机制已成立的假设扩量。本候选方向不自动命名为已成立的DARC v6。

## 1. 为什么现在调整

三轮受控开发实验逐渐削弱了“完整决策对比报告具有独特收益”的假设：

| 已完成实验 | 观察 | 能说明什么 |
|---|---|---|
| 24例注入错误，Fields与DARC | 语义正确18/24与23/24 | 受控错误下存在提示/信息收益线索，非自然错误效果 |
| 统一提示三信息组，两次重复 | Fields36/48、路线顺序42/48、完整报告44/48；后两者TSR均48/48 | 完整报告独有增量很小，且含格式失败与单一母意图影响 |
| 依赖文字化与路线顺序，两次重复 | 语义39/48与41/48，但TSR47/48与45/48，路线tokens多19.6% | 不能证明求解器是有效复核的必要环节；路线组独有正确来自偏好方向，不是依赖修复 |

依据：`docs/experiments/v5_1/CONTROLLED_MECHANISM24_20260910.md`、`MECHANISM_ABLATION24_20260910.md`、`DS_DEPENDENCY_TEXT_CONTROL24_20260910.md`。24例仅复用8个母意图，不将重复调用作为独立证据，不以更换模型或继续调整这批数据来维持旧结论。

## 2. 新问题：条件指令如何正确映射到场景中的对象

候选题目（工作题，不是投稿标题）：

**面向场景条件指令的POI选择：语言解析、确定性求解与复核证据的受控比较**

英文工作题：**Grounding Scene-Conditional Instructions for POI Selection: A Controlled Study of Parsing, Solving, and Verification**。

关注明确可执行的表达，如“完成银行业务后能在药房关门前办完事的最近药房”“能在指定时刻回家的最高评分药房”。用户的规则可保持不变，而正确POI会随营业时间、位置等变化。必须区分规则层与对象落地层：图改变时规则不应漂移，具体地点改变可以是正确适应。

核心研究问题：同一份公开场景事实下，模型先解析明确规则再由确定性执行器处理，是否已经足够？如果仍有规则误读，计算得到的时间/距离证据能否比纯语言复核带来额外净纠正？

这里“场景必要”只表示答案依赖场景事实，不表示一定需要LLM复核，更不表示必须使用复杂规划器。新设计要主动允许更简单系统胜出。

## 3. 候选方法与强对照

初步采用两层接口：

1. 语言规则：访问顺序、候选资格条件、开放时间参照点、回家截止、明确选择准则。
2. 确定性落地：枚举公开候选，计算行程时刻和目标量，输出所有并列最优可行对象或INFEASIBLE。

不再把模糊偏好强行压成唯一连续权重。最近、最小额外距离、最高评分分别使用明确的目标字段，不加哈希风险分数或选择性门控。

主方法候选为一次场景证据复核：先得到规则解析，再以公开场景和候选行程计算表辅助复核，修订后由同一执行器求解。它只是待验证方案；如果“规则解析＋求解”已饱和，就没有理由保留复核模块。

必须具备三个主对照：直接规则解析＋执行器；纯语言复核＋同一执行器；计算证据复核＋同一执行器。三者都看到完整原始场景，纯语言组也看到相同候选解析。禁止让计算组独享营业时间或位置来人为制造优势。方法侧执行器只能接受模型预测规则，不能读取作者规则标签。

暂不延续旧A/B候选门控或复杂完整报告。先检验一次解析的错误是否存在、一次证据复核是否必要；候选对比结构只有在独立增量有证据后才考虑加入。

## 4. 已有基础与benchmark边界

本节为2026-09-10的定向官方来源核查，未完成穷尽文献检索或最新榜单审计。

| 来源 | 官方资料支持的事实 | 对本项目的定位 |
|---|---|---|
| [LLMAP官方仓库](https://github.com/liangqiyuan/LLMAP) | 公开自然语言偏好与多目标路线规划项目及HIPP来源 | 保留历史语言任务连接；本轮作者构造的12例不是HIPP原测试集，不延用其榜单名义 |
| [TravelPlanner官方仓库](https://github.com/OSU-NLP-Group/TravelPlanner) | 多约束旅行计划评估，提供环境与评估代码，区分环境、常识及硬约束 | 是后续外部验证候选，完整任务涵盖交通、饮食、景点和住宿，不能把本轮小型POI选择称为其复现 |
| [TripCraft，ACL 2025](https://aclanthology.org/2025.acl-long.834/) | 关注时空连贯旅行规划，包含公交时刻、事件等现实约束 | 时空条件不是本项目新提出的方向；值得进一步检查是否存在可透明抽取的子任务，目前未下载审计数据或完成适配 |
| [Personal Travel Solver，ACL 2025](https://aclanthology.org/2025.acl-long.1339/) | 结合LLM与数值求解器处理明确约束及隐含偏好，提出RealTravel | “语言模型＋求解器”已有，不能作为新颖性主张；需要进一步阅读方法与代码才能确定公平基线适配 |

现在没有足够依据指定一个可直接发表SOTA比较的外部benchmark。12例仅命名为`Scene-Pilot12`内部开发夹具，非公认基准。若机制小验证有希望，必须再审计公开数据许可、字段/时刻/位置可用性、评分器和未暴露划分，形成外部验证协议后才进入正式proposal修订。

可能的研究价值是清楚区分“语言规则误读”“场景算术/求解错误”“复核诱导改坏”，并以场景最小变化对检验规则保持与对象适应；是否具有足够新颖性和会议价值仍需后续证据，不承诺录用。

## 5. 本次交付与结束条件

已设计12例、6个最小变化对：3对改场景属性、2对改明确语言条件、1对不可行情形下无关属性变化。10例有唯一可行最优对象，2例明确不可行。作者手算预期与离线参考计算一致，尚未人工语义审核，无模型API调用。

这一批故意保持规模小且定义明确，用于检验接口与假设，而不承诺打破强模型天花板。相关样本不得因为“模型都做对”而被静默替换。

后续小验证的研究判断：直接解析若12例两次均正确且对象选择正确，停止此分布上的复核扩量；若有错误但计算证据不优于语言复核或改坏抵消收益，停止本方法扩量；若有跨至少两个规则族的净纠正、无额外任务退化，再考虑独立新开发样本。上述是开发投资判断，不是显著性阈值或论文成功证明。
