# DARC-Route v4：面向 EI 会议的可执行研究方案

**英文题目：DARC-Route: Decision-Aware Selective Verification for Language-Based POI Route Planning**

**中文题目：DARC-Route：面向自然语言 POI 路线规划的决策感知选择性复核**

版本日期：2026-09-05。目标：以 CCEAI 2027 为候选的 EI 会议论文。状态：研究设计，尚无实验结果。配套文件：`DARC_Route_CCEAI2027_Review_v3.md`。本方案保留 DARC-Route 项目名，重新定义实施范围；v3 原稿保留。

## 1. 研究决策摘要

本项目研究一个问题：**在自然语言解析结果存在分歧时，利用其对路线规划的影响，能否比仅看语义分歧或随机抽样，更有效地分配有限的 LLM 复核预算？**

推荐的最小论文由三部分组成：两个提示产生候选解析；固定小型路线求解器提供决策差异信号；在人工核验的等义指令组上比较任务质量与成本。

| 内容 | v4 决定 |
|---|---|
| 语言数据来源 | 复用公开 HIPP，构建有来源记录的等义扩展 |
| 正式规模 | 200 个不同意图组，每组原句＋3 个改写，共 800 句 |
| 主路线环境 | 固定的小型合成 POI 图，离线、可枚举；明确为受控实验 |
| 主求解器 | 精确枚举候选路线，所有方法共享；不声称直接复现原 MSGS |
| 方法 | 两路直接读原句，硬约束保护＋决策差异门控，最多一次复核 |
| 核心主张 | 在明确预算下改善任务质量，或相对始终复核减少成本且质量变化可接受 |
| 必做对照 | 单次解析、三次自一致性、双路不复核、随机门控、语义门控、硬约束门控、始终复核 |
| 非必做 | 原 MSGS 适配、真实地图小样本、第二模型完整重复 |
| 移至后续 | TransitLM、多模态、车辆控制、学习式仲裁器、新模型训练 |

默认资源假设：一名主要研究者、一名协助标注者，约 6 周；能调用一个固定版本的基础模型，另有一种模型可做小规模核查。此为规划假设，不代表团队已承诺这些资源。

## 2. 定位与待检验贡献

LLMAP 提供了自然语言偏好到路线规划的任务基础；其公开 HIPP 可作为语言来源。[LLMAP 原文](https://arxiv.org/abs/2509.12273)

本项目拟检验的两项贡献为：

1. **选择性复核规则。** 对结构性分歧强制复核，对只有数值偏好分歧的情况，用同一场景中候选路线的决策差异决定是否追加一次复核。
2. **受控评估协议。** 将经过核验的等义组、语义改变对照和固定图结合，联合评价任务满足、语义正确性、效用差异及真实推理成本。

决策误差与参数误差的区别已有 SPO 等研究；我们的目标是推理时的复核调度，不提出新的决策学习理论，也不声称首次将规划结果用于验证。[Smart “Predict, then Optimize”](https://doi.org/10.1287/mnsc.2020.3922)

论文应用范围为离线 POI 行程规划。结果若成立，可启发其他语言接口，但不自动外推为真实导航、实时自动驾驶或安全保证。

## 3. 研究问题与检验顺序

| 问题 | 要回答的内容 | 证据 |
|---|---|---|
| RQ1 | 等义变化是否造成任务错误，而非仅造成 JSON/路线 ID 变化？ | 原句与改写的配对任务满足率、语义错误和路线差异 |
| RQ2 | 决策信号是否带来超出结构分歧的增量？ | 固定候选、复核器和预算，对比不同门控 |
| RQ3 | 选择性复核是否有质量—成本优势？ | 任务满足率、token、延迟及规划次数的联合比较 |

先验证复核器本身是否能改善错误；如果始终复核都没有收益，优化其调用时机通常没有必要。所有问题都是待检验假设；不预写“我们显著提升了”等结果句。

## 4. 任务定义与语言标签

输入为原句 `x` 和固定场景 `G`，输出为一条访问 POI 的路线或明确的失败状态。

结构化意图：

\[
y=(S,T,D,w),\qquad w\in[0,1].
\]

- `S`：请求的 POI 类型集合；HIPP 五类为 shopping_mall、supermarket、pharmacy、bank、library。
- `T`：最晚结束时间，未提出则为 null；内部统一为场景日期内的分钟数。
- `D`：有向先后依赖集合；按可达关系比较语义，避免把冗余传递边当作分歧。
- `w`：质量权重，距离权重为 `1-w`；属于求解接口中的校准量。
- 开门时间、距离、出发时间和停留时长来自场景，不由解析器猜测。

**标签分层：**

| 标签 | 来源 | 用途 |
|---|---|---|
| `S_gold,T_gold,D_gold` | HIPP 原标签经原句人工核对 | 主要语义与任务评价 |
| `preference_direction` | 人工只看文本，标为质量优先/距离优先/均衡/无法判断 | 偏好方向正确率 |
| `w_syn` | 原 HIPP 合成权重，保留原值 | 辅助参考，不当作唯一真实偏好 |
| `w_eval` | 从方向标签按预定规则映射 | 受控效用评价，并做映射敏感性分析 |

主校准为质量优先 0.75、均衡 0.5、距离优先 0.25；稳健性分析改为 0.65/0.5/0.35 和 0.85/0.5/0.15。三组值是**研究者设定的评测规则**，不是测得的人类偏好。无法判断的样本保留用于任务与硬约束评价，但不进入方向正确率和方向校准效用的分母，并报告数量。

直接预测的 `w` 大于、等于、小于 0.5 对应三个方向；解析器明确按此 schema 工作。权重接近 0.5 的细微波动另作连续量诊断，不能仅靠方向分类放大成严重规划错误。

暂不新增软截止时间、预算约束、交通方式或需要用户交互的澄清任务。这些超出当前 schema。

## 5. HIPP-Robust 数据构建

### 5.1 来源与复现边界

冻结公开 LLMAP 提交 `281f6ad95f42ca386400e5288f006aeffa2ac282` 的 `dataset/HIPP.json`，保留原始索引与文件哈希。当前 JSON 有 1,000 条语言记录，但缺少原主程序所需的完整地图场景和中间文件。因此本研究复用其语言数据，使用自行公开的受控图；不得把结果写成原文完整路线实验复现。[固定数据版本](https://github.com/liangqiyuan/LLMAP/blob/281f6ad95f42ca386400e5288f006aeffa2ac282/dataset/HIPP.json)、[原入口](https://github.com/liangqiyuan/LLMAP/blob/281f6ad95f42ca386400e5288f006aeffa2ac282/main/main.py#L33)

HIPP 的 natural-language instructions 是合成数据。数据说明必须写清生成来源；“人工核验过”不等于“原始人类用户采集”。

### 5.2 先去重，再划分，再改写

按 `S`、标准化 `T`、依赖传递闭包及人工偏好方向形成语义簇；对明显近重复文本进一步检查。不能仅因原始 index 不同就视为独立意图。

按预定随机种子从可用簇选取 200 个意图代表，覆盖 POI 数、时间约束和依赖有无、偏好方向。若某些组合稀少，使用边际分层并报告分布，不强行凑满所有组合。若审核后不足 200 簇，按原抽样规则递补，不能依据任何方法表现选样。

- 开发：40 组，其中 20 组用于最早 pilot；另 20 组用于门控与提示校准。
- 测试：160 组，在 pilot 前冻结组 ID；不向方法开发暴露测试文本、标注或结果。
- 每组 4 句：原句、直接同义改写、句式/语序改写、可恢复轻微拼写/口语变化。
- 正式规模为 200 个意图、800 句；测试是 160 个组、640 句。

同一原始意图及其相近语义簇只能出现在一个 split。标注人可以审核测试集，但不将测试标签用于提示或阈值设计。

### 5.3 等义审核流程

1. 对原句先列出 POI、时间、依赖、偏好方向及证据片段；发现原句与原标签冲突时记录并排除出严格等义主集。
2. 生成器只改变表达，不添加身体状态、交通方式、数值限制或新目的，也不删除关键条件。
3. 标注者 A 核验所有 800 句；B 独立复核随机分层抽取的 25% 组的全部句子及所有争议组。两人先独立判断，再共同裁决。
4. 报告字段一致率、偏好方向一致率和争议处理。二次复核若发现超过 5% 的句子有语义变化，扩展为对全部组双人检查，修改后再冻结；5% 是工作流触发值，不是数据质量达标证明。
5. 对被改写模型“补全”的遗漏不得默认通过。语义变化或无法确认的版本重写，记录拒绝原因；不把它们混入等义主集。

生成模型、生成提示及标注过程与被测系统的运行过程分开。系统推理一次只读当前一句，不读其他改写、base ID、gold、人工方向标签或原合成权重。

### 5.4 小型语义改变对照

从主集之外另取 40 个审核过的意图，每个构造一对最小改变，共 80 句。两句各自有标签，不参与等义一致性统计。优先改变明确时间、反转依赖或删除某条依赖；偏好方向改变只用于方向及效用诊断。

报告两侧分别解析正确的比例；只在精确求解确认改变确实影响可行集或最优决策的子集上评价路线响应。不得把“路线未变”一律判错，也不得用这组测试调门控。若要开发其生成模板，使用开发集材料完成。

## 6. 固定路线环境与精确后端

### 6.1 为什么主实验不用原 MSGS 作为最优参照

原源码的数据接口、负边权搜索、依赖编号及早停等细节需独立审计。目前不能假定直接运行即可获得可靠最优解。EI 论文的主问题是复核调度，优先使用能验证正确性的小型确定性后端，降低非核心风险。[原规划代码](https://github.com/liangqiyuan/LLMAP/blob/281f6ad95f42ca386400e5288f006aeffa2ac282/main/utils.py#L177)

所有方法共享新后端。单次解析基线称 **LLMAP-style parser + fixed solver**；不称复现的原 LLMAP 系统，也不与原文不同地图上的数值直接比较。

### 6.2 图规模与场景生成

每个意图绑定一个图，同组四句使用完全相同的图。图包含固定起终点和每类 2 个候选 POI，共 10 个 POI；包含所有五类，避免图中只有 gold 类型而泄露答案。固定 POI ID、坐标、质量属性、边距离/行驶时间、开放时段和停留时长。

主环境采用二维坐标距离及固定速度生成路程时间；这是合成规划图，不是真实道路网络。质量由归一化评分和评价数量组成，停留时长按类别配置。时间全用分钟；明确采用到达后可等待开门、服务结束不晚于闭店、最终到达不晚于截止时间的规则。

场景生成器固定版本和种子，预设宽松、时间较紧、质量与距离有明显权衡三类配置；按结构属性而非模型表现检查分布。图在推理前冻结，不按解析结果重新检索或生成。

主集要求 gold 请求存在至少一条完整可行路线，便于解释“任务全部满足”。可按固定、最多 20 次的场景重采样规则满足可行性；失败组按预先抽样顺序递补。完整公开重采样/剔除计数及主集的可行性条件，不能称为自然流量分布。语义改变后变为不可行的案例单列。

### 6.3 求解目标

先满足硬约束，再最大化请求类型覆盖数，最后最大化质量—距离效用。每个类型至多访问一个候选 POI。

\[
U_w(r)=wQ(r)-(1-w)\bar D(r).
\]

`Q(r)` 为访问 POI 的平均归一化质量，值域 [0,1]；空路线为 0。评分与对数评价数量各占质量的一半，其缩放常数由图冻结后统一确定。`D_bar` 为路线总距离除以 `(5+1)×图中最大边距离`，值域 [0,1]；全图最大边距离为零的退化图在生成时排除。因此 `U` 位于 [-1,1]。

缩放不随预测 POI 集合或候选路线变化。缺失或无效属性在冻结图时统一处理。此效用是公开的受控模型，不代表真实用户效用，也不声称与原 MSGS 数值完全相同。

五类各两个候选的全部非空路线数量为：

\[
\sum_{k=1}^{5}\frac{5!}{(5-k)!}2^k=6330.
\]

加上直达路线共 6,331 条；可预计算图上每条路线的类型、顺序、时间和质量，再根据预测意图过滤及评分。按 `(覆盖数,效用,稳定POI序列)` 确定唯一结果，浮点容差固定为配置项。禁止访问未请求的 POI 作为任务节点。

求解器接收预测标签；评估器使用独立保存的 gold 标签。对未知 POI、循环依赖、格式错误或时间无效返回显式状态，不能静默将有问题的约束删除。

### 6.4 最小正确性检查

在不调用 LLM 的小图上检查：超时、闭店、依赖反转、空请求、多个同分最优路线、无可行路线，以及“预测漏掉约束但 gold 评估会拒绝”的例子。手算少量 2—3 类图，独立暴力枚举与生产筛选实现交叉检查。

原 MSGS 如后续能完成数据适配和上述检查，可在冻结测试子集上补充稳健性实验；任何修复对全部方法统一生效，并将其标为 adapted implementation。它不影响最小论文是否能够完成。

## 7. DARC-Route 方法

### 7.1 两个互补候选

- A：用直接结构化提取提示读取原句，输出 `S,T,D,w`。
- B：用逐字段证据提示读取同一原句，输出相同 schema 和简短原文证据片段。

两路使用同一模型版本和相同解码预算，不互相看输出。它们是不同提示下的互补候选，**不假设统计独立**。不再先生成 canonical text 再解析，基础调用从 v3 的三次减为两次。

公共 schema 校验负责类型、枚举、时间、权重和依赖合法性。仅允许预先定义的无语义修复，如字段别名和时间格式转换；记录原始与标准化结果。不能把未知值自动改成“无约束”。

### 7.2 先检查结构分歧

令 `H=(S,T,closure(D))`。出现以下任一情况，触发一次复核：候选解析无效、两路 `H` 不同、任一路规划报错或无解、或两路覆盖请求的数量不同。即使当前路线相同，硬约束分歧也不能被决策信号覆盖。报错/无解不进入效用差值计算；两路都只完成部分任务的情况另作失败诊断，不凭一致性称为正确。

如果两个有效意图完全一致，可缓存复用一次规划。其他情况至多先求两条路线 `r_A,r_B`。

### 7.3 决策差异门控

在两路结构一致、均有合法规划且覆盖数相同的情况下，分别用两组预测权重对两条候选路线交叉评分：

\[
\Delta_U=\max_{j\in\{A,B\}}
\left|U_{w_j}(r_A)-U_{w_j}(r_B)\right|.
\]

最终触发规则：

\[
g(x,G)=\mathbb{1}[\text{结构/状态分歧}]
\lor\mathbb{1}[\Delta_U>\tau].
\]

`Delta_U` 是归一化受控效用上的分歧，不是观测到的真实 regret。路线 ID 不同但两路评分都近似等价时，可以不追加复核。它不使用 gold 权重、gold 路线或测试标签。

仅有一个效用阈值 `tau`，在开发集上从固定网格选择。候选网格可用 0、0.01、0.025、0.05、0.1、0.2、以及关闭效用触发；网格及选择规则在正式实验前冻结。v3 的多系数 risk、`1/(margin+epsilon)` 和 top-2 全部取消。

开发阶段按预设复核预算上限选最高任务满足率的阈值，并列时选择 token 更低者。硬约束保护调用率若已经超过预算，则报告预算不可达，不允许通过忽略硬约束分歧凑预算。

### 7.4 最多一次复核与输出规则

复核器输入原句、两份候选及字段分歧；要求对最终字段提供原文依据并输出一个完整结构。**规划结果用于门控，复核器不看候选路线质量或 gold。** 这样可以更清楚地区分“规划决定是否花钱”与“语言决定用户意思”。

- 未触发：保留 A，不进行数值均值或字段拼接。
- 触发且复核结果有效：采用复核结果，最多再求解一次；若与已有候选相同，复用缓存。
- 复核结果无效：A 有效则回退 A；否则 B 有效则回退 B；均无效则返回解析失败。
- 语义矛盾且不能给出有效结构、规划无解或超时：输出显式失败/不可行状态。对主集可行任务记为失败，不从分母删除。
- 不进行多轮追问或自动追加推理。纯网络故障统一有限重试，全部计入成本；语义错误不以网络重试名义重跑。

复核器可能改坏原本正确的答案。测试时必须记录“纠正数、引入错误数、无变化数”，不得以有复核器为理由宣称输出受保证。

```text
原句 x ──→ 直接解析 A ───────┐
       └─→ 证据解析 B ───────┤
                            ↓
                  结构检查＋固定图规划
                            ↓
                 结构分歧 或 效用分歧 > τ
                    否 ↙           ↘ 是
                   保留 A       一次原句证据复核
                       ↘         ↙
                      固定求解器 → 路线/失败状态
```

## 8. 基线与消融：优先证明门控增量

所有主方法使用同一模型、图、字段定义、求解器和失败策略。历史 HIPP 模型输出只用于数据理解，不代替重新运行的公平基线。

| ID | 方法 | 作用 | 名义 LLM 调用/句 |
|---|---|---|---:|
| B0 | 单次直接解析 A | 最简单工程基线 | 1 |
| B1 | 三次直接解析，自一致性选择完整候选 | 测试多次采样本身的收益 | 3 |
| B2 | A+B，不复核，保留 A | 门控成本与收益的控制；准确率理论上应与 B0 相同 | 2 |
| B3 | A+B，随机复核 | 同预算调度基线 | 2+q |
| B4 | A+B，结构分歧或权重差触发 | 仅表示层门控 | 2+q_sem |
| B5 | A+B，只在结构/状态分歧时复核 | 隔离软偏好决策信号的增量 | 2+q_hard |
| B6 | A+B，每句都复核 | 质量与最大复核预算的参照；不保证一定最优 | 3 |
| Ours | A+B，结构保护＋效用差异触发 | 主方法 | 2+q_darc |

B1 使用完整候选 medoid，不逐字段拼装；候选距离为离散字段差＋权重距离，固定平局选择规则。距离和所有 prompt 仅用开发集设定。

B4 与 Ours 使用相同结构保护，只把效用信号替换为 `|w_A-w_B|`。B3 在相同结构保护之外，对剩余样本随机复核；另报告纯随机抽样作辅助对照。随机种子预固定，复核输出可复用作多种随机掩码评价。

两类预算比较同时保留：

1. **可部署策略比较：** 在开发集匹配目标复核率并冻结策略，测试报告实际调用率和 token，不假设自动精确相等。
2. **离线相同配额诊断：** 在相同结构保护的基础上，对剩余测试案例按效用/表示分歧排序取相同数量，与随机取样比较；不使用测试标签选配额。明确这是一种批量预算分析，不能冒充单请求在线阈值策略。

如只有 B0 显著落后，而 Ours 不优于 B4/B5/同预算随机，则不能声称决策门控具有额外价值。

## 9. 指标及防止“稳定但错误”

### 9.1 主指标：任务满足与成本

在已确认 gold 完整可行的主集上，定义：

\[
A_{ik}=\mathbb{1}[r_{ik}\text{合法且覆盖全部 }S_i^{gold},
\text{满足 }T_i^{gold},D_i^{gold}\text{及开放时间}].
\]

逐句任务满足率 `TSR = mean(A_ik)`；严格组鲁棒满足率：

\[
GTSR=\frac1N\sum_i\prod_{k=0}^{3}A_{ik}.
\]

主报 TSR，GTSR 作为等义鲁棒性的关键补充，并分别展示原句与三类改写。两者评价任务与硬约束，不代表软偏好完全正确；偏好方向与效用单独报告。

成本主报输入/输出 token 和端到端时间，附复核率、LLM 次数、规划次数、失败与重试次数、峰值内存。若使用付费 API，以实验当日真实价格换算费用并标明日期；当前不编造价格。

### 9.2 次指标

| 层次 | 指标 | 防误读规则 |
|---|---|---|
| 解析 | POI F1、时间精确匹配、依赖闭包 F1、偏好方向正确率、格式失败率 | 空依赖双方都空的计分规则固定；各分母公布 |
| 约束 | gold 时间/依赖/开放时间违反率、丢失任务比例 | 绝不按预测约束自我打分；空路线不能算任务完成 |
| 路线 | 同组两两 Route Flip Rate | 用稳定 POI ID；仅作诊断，不能单独证明改善 |
| 偏好 | 固定校准效用差、原始合成权重偏差 | 合成参考/人为校准与真实偏好严格区分 |
| 门控 | 复核错误召回、改正/改坏比例、未触发但失败比例 | 只在冻结后的离线评价使用 gold |

对共同满足全部任务与硬约束的路线，计算：

\[
L_U=\frac{U_{w_{eval}}(r^*)-U_{w_{eval}}(r)}{2}.
\]

`r*` 是同一 gold 任务、同一图、相同权重和完整覆盖条件下的精确最优路线。`L_U` 位于 [0,1]，容差内的微小负数按数值误差处理，其余负数触发求解/评估检查。失败或未完成任务的输出不进入条件效用均值，但必须同时报告其数量和 TSR，防止幸存者偏差；另可展示将失败赋最大损失 1 的综合敏感性结果，并标明人为惩罚。

对无法判断偏好方向的样本不计算 `w_eval` 效用。原 `w_syn` 下的结果仅为附加诊断，不用于声称恢复了真实用户偏好。近等价路线的翻转可按预注册效用容差另列，而非混入任务失败。

### 9.3 统计与重复

- 同一意图四句先聚合；按语义组进行配对 bootstrap，2,000 次得到差值的 95% 区间。
- 若审计发现多个组仍共享同一语义簇，则按更高层簇重采样并报告有效簇数。
- 一次冻结测试主运行；在预先抽取的 40 个测试组上，对 B0、B4、B6、Ours 重复运行 3 次检查模型随机波动。这些重复不能当作新的独立意图。
- 主要对比事先指定为 Ours 对 B4 和同预算 B3；B5 用于判定增量来源。多项正式显著性检验时做 Holm 校正，否则将其他分层比较标为探索性。
- 160 个测试意图适合初步会议研究，但未完成统计功效估计，不保证检出微小改善。区间过宽时收窄结论，不将“不显著”当作相同或等效。

## 10. 可复用缓存与成本预算

设复核率为 `q`，理想情况下：

\[
C_{LLM}^{DARC}=2+q,\quad C_{LLM}^{always}=3,
\quad C_{LLM}^{single}=1.
\]

因此相对始终复核的**调用次数**节省为 `(1-q)/3`；当 q=0.3 时约 23.3%。它不是节省了 70% 的总成本，更不是比单次解析便宜。两路并行可缩短延迟，但不减少 token。

规划调用最多约 `2+q`，重复意图可复用；必须记录求解前处理和最终评估以外的真实运行成本。共享两路解析及复核输出可以减少本研究实验账单，但每种方法的部署成本须按它实际需要的调用重建。

测试主集 640 句可预先保存 A、B、一次统一复核结果；B1 可复用 A，再增加两个直接解析样本。这样各门控条件可在冻结候选与同一复核器下比较，约需 `640×5=3,200` 次基础调用。离线为所有句子计算复核结果仅为公平比较和复用，不能声称选择性方法在线也看到了未触发的复核答案。

含开发试验、80 句语义改变对照、重复及可选第二模型，先预留 **6,000—10,000 次调用**作为工作量范围。实际费用以 pilot 测得的平均 token、模型价格和重试率估算：

\[
\text{费用}=\sum_m(N_{in,m}p_{in,m}+N_{out,m}p_{out,m})/10^6.
\]

不要求本地训练或高端 GPU。若预算紧张，先省去第二模型完整测试和外部环境，不删除同预算门控对照及人工审核。

## 12. Go / No-Go：避免带着无效假设扩量

这些阈值是本项目建议的开发决策规则，不是已知结果，也不是会议录用门槛。

### Gate A：第 1 周结束

- 20 个开发意图及 80 句审核可用，小图求解/评估检查通过。
- 基线确有可解释的语言或约束错误；若任务错误几乎为零，则当前自然等义分布可能存在天花板。可以预先定义并另列更难的诊断集，但不能暗中挑错例替换主集。
- 始终复核至少出现净纠错，并跨多个意图而非单一模板。若只改坏或完全无收益，最多用开发集修改提示一轮；仍失败则停止扩量。

### Gate B：第 3 周冻结前

- 两路对部分样本确有分歧，且软偏好导致的效用差异并非总为零。
- 效用门控在开发数据上能区分值得复核的样本，且不只是复制硬约束触发。
- 若始终复核有效但效用信号无增量，保留更简单的结构门控作为候选结果，停止使用“决策信号有效”的主张；如转题，应重新写研究问题并安排未见测试验证。

### Gate C：正式结果后的主张规则

理想的工程证据是：相对表示门控/随机门控，在相近实际 token 预算下任务满足率提高；或相对始终复核，节省可观 token 且质量损失有明确边界。

可预注册相对始终复核 TSR 降低不超过 **2 个百分点**为工程容忍范围，并期望 token 至少节省 **15%**。只有配对区间支持该容忍范围时，才使用相应非劣表述；2 和 15 都是设计目标。若区间跨出范围，就报告实际差异，不能把未检出显著差异写成“同等性能”。

如果只降低 route flip，却损害任务满足或效用，不认定方法有效。若效应不足，交付透明的诊断结果并重新评估是否适合方法论文；不能保证仅靠负结果即可达到目标会议要求。

## 16. 开题时的可用表述

> 本研究拟考察自然语言 POI 路线规划中的选择性复核问题。我们以公开 HIPP 指令为来源，构建经人工核验的等义表达组，并在冻结的小型规划图上使用统一的精确求解器。所提出的方法根据两个候选解析的结构分歧及其对路线效用的影响，选择性调用一次原句证据复核。实验将对比随机复核、仅语义分歧复核和始终复核，检验规划后果能否提高有限复核预算的利用效率。所有性能、成本和泛化结论均以冻结测试结果为准。
